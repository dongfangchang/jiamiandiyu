# v0.9.1 试玩阻断修复与 QA 门禁

## 1. 版本信息

- 日期：2026-11-08
- 状态：已关闭
- 类型：补丁版本 / 阻断修复
- 主题：修复抽卡与战斗无法退出、卡牌信息缺失、反馈不直观和发布测试缺口
- 用户价值：把当前工程从“能跑”提升到“可以连续试玩且不会卡死”

## 2. 发布硬门

本版本不新增途径、章节或卡池。只有以下检查全部通过，才能关闭版本或开始下一项功能：

1. 所有现有单元、玩法、数据、UI、集成和数值测试通过。
2. Godot headless 主场景无解析错误、资源缺失或非零退出。
3. 使用新增测试角色完成至少一轮普通路线和两条挑战。
4. 实际窗口内完成抽卡、退出抽卡、战斗、投降退出、继续游戏与路线失败恢复。
5. 截图确认 16 张卡均显示中文名称、有效图像或明确占位，不出现内部英文 ID。
6. 实际窗口确认打出卡牌与受击有伤害数字、血条/护盾变化、目标高亮和事件日志。
7. Windows 独立构建在项目目录外启动，关键流程无 S1 问题。
8. QA 记录与产品经理验收记录均已写入本版本文档。

## 3. 必须修复

### S1 阻断

- 抽卡完成后 pending 未恢复、界面不刷新、返回按钮无法恢复。
- 战斗中无退出/投降入口，玩家只能强制关闭程序。
- 战斗手牌显示 `lantern step`、`warding circle`、`coffin nail` 等内部 ID。
- 卡牌图像缺失并显示“灵界残留”占位，未给出可理解的卡牌功能。

### S2 严重体验

- 打出卡牌、受到攻击只显示文字，没有清楚的命中、伤害、生命与护盾变化。
- 路线中断缺少明确原因、保留内容说明和恢复入口。
- 抽卡、战斗和成长页面的返回/取消规则不一致。

## 4. 角色任务

### UI

- 修复 gacha pending 锁与返回路径；任何请求完成或失败后必须恢复交互。
- 战斗增加“投降并返回最近检查点”入口与二次确认。
- 手牌在战斗内显示中文名称、费用、目标、完整效果和等级。
- 增加卡牌打出、命中、伤害、治疗、护盾和受击的可见反馈。
- 路线中断页显示具体失败节点、失败原因、已保留内容和返回/重试入口。

### 应用 / 数据层

- 排查 pending 状态未恢复的根因，移除永久锁死路径。
- 确认所有卡牌显示名、效果和图像从 v0.7 正式内容映射，不显示内部 ID。
- 增加本地测试角色入口；测试角色提供全卡、足够资源和已解锁挑战，但不影响普通进度。
- 为 gacha 退出、战斗投降、卡牌翻译和路线中断补充集成测试。

### 玩法

- 提供卡牌战斗详情所需只读字段；不在 UI 内计算效果。
- 明确投降命令的语义：放弃当前战斗，回到最近检查点，不发放未确认奖励。
- 明确路线中断的稳定原因码和玩家可执行恢复动作。

### QA

- 新增 v0.9.1 自动化用例和人工操作清单。
- 使用测试角色按用户截图路径复现所有问题。
- 只有发布硬门全部通过后，才能标记 QA PASS。

## 5. 可借鉴的成熟交互模式

允许借鉴类型游戏的通用信息架构与交互模式，不复制代码、美术或具体内容：

- 手牌悬停/点击展开完整效果与升级变化。
- 选牌后高亮合法目标，非法目标与资源不足立即反馈。
- 出牌后伤害数字、目标震动、生命/护盾条变化、战斗日志同步。
- 抽卡操作期间显示明确的处理中状态，完成或失败后恢复按钮。
- 战斗提供投降/退出确认，退出后回到最近检查点。
- 路线失败明确区分战斗失败、污染失败、仪式失败和主动退出。
