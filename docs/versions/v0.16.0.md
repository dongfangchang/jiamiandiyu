# v0.16.0 UI 改进与可玩性体验同步

## 1. 版本信息

- 日期：2026-11-08
- 状态：已关闭
- 类型：UI 体验补丁
- 主题：统一信息层级、操作反馈和小窗口下的可玩性提示
- 用户价值：玩家能更快看懂当前状态、下一步可执行动作和操作结果，减少因反馈不清造成的误操作。
- 前一版本：`v0.15.0`，已关闭；macOS 开发工具入口已完成

## 2. 范围

### 必须交付

- 统一启动页、身份、路线、战斗、奖励、抽卡、升级和结果页的标题、状态摘要与主要操作层级。
- 为可执行、暂不可执行、处理中和完成状态提供一致的视觉反馈；反馈只呈现已有快照、事件和原因码。
- 改善战斗页和牌组页在小窗口下的操作入口可见性、聚焦状态和滚动提示，不改变布局契约中的 1600×900 基准。
- 让关键操作结果在页面内有明确、短暂且可读的反馈，避免只依赖颜色或日志。
- UI 角色在实际窗口或等效截图中完成审稿，QA 增加对应的重复点击、非法阶段、窄视口和空数据回退检查。

### 明确非目标

- 不新增或修改卡牌、敌人、战斗公式、抽卡概率、成长数值、路线规则或存档 schema。
- 不新增第二途径、第二章节、联网服务、插件或新的稳定资源 ID。
- 不由 UI 计算伤害、概率、合法性、胜负或玩法状态；仍只消费只读视图模型、事件和稳定原因码。
- 不让美术和 UI 由同一角色制作并验收同一批正式资产；若发现资产问题，提交美术候选和 UI 审稿结论。

## 3. 角色任务与依赖

- 产品经理：冻结本版本范围，审核跨角色请求，维护版本与验收文档。
- UI 设计：只修改 `src/ui/**`、`scenes/ui/**`、`assets/ui/**`、`tests/ui/**` 及 UI 报告；先盘点共用组件，再实现反馈和可读性改进。
- 玩法设计：只读审查现有快照、事件和原因码是否足够表达 UI 需求；不得修改玩法规则，缺少语义时提交请求。
- 本地数据层：确认 UI 改进不绕过应用装配、存档和内容端口；只有出现接口缺口时才提交端口请求。
- 美术：仅在 UI 审稿发现正式资产缺口时提供候选资产和制作报告；不直接修改 UI 业务逻辑。
- QA：覆盖 UI 单模块测试、重复与非法状态、窄视口真实窗口或截图、headless 启动和格式检查。
- 主协调者：集成各角色交付物，负责共享契约审查、最终质量门、提交和推送。

依赖顺序：产品经理冻结范围 → UI 盘点并实现 → 玩法/数据层审查语义缺口 → UI 与 QA 回归 → 主协调者集成和发布检查。

## 4. 验收标准

1. 主要页面的标题、状态摘要、主操作和次操作层级在实际 1600×900 页面中一致可辨。
2. 关键控件在默认、聚焦、按下、禁用和处理中状态下有可见差异，且不会把合法操作永久锁死。
3. 战斗与牌组页在 1280×720、1366×768 等较小视口下仍能发现并到达主要操作入口。
4. 重复点击、非法阶段命令、空数据和未知原因码不会造成崩溃、重复结算或不可返回页面。
5. UI 测试、headless 启动、截图或等效窗口审稿、`git diff --check` 全部通过。
6. 代码 diff 不包含玩法规则、数值、存档 schema、共享 core 契约或正式资源稳定 ID 的未批准修改。

## 5. 风险与回滚点

- 共用 UI 主题调整可能影响多个页面；先保留基准尺寸和现有资源路径，按页面逐项回归。
- 反馈文案若脱离原因码可能与真实动作不一致；所有状态文案必须来自快照、事件或稳定映射。
- 小窗口适配可能重新引入裁切；必须使用实际窗口或截图检查，而不能只依赖 headless 退出码。
- 回滚点为 `56ed4f4`（v0.15.0 已验证提交）；回滚时保留独立、无关的文档或角色报告修改并由产品经理记录。

## 6. 关闭条件

- UI 报告记录每个页面的通过、仅 UI 适配或需要美术返工结论。
- QA 报告记录自动化、破坏性路径、窄视口和实际窗口证据。
- 产品经理确认范围未扩展到玩法、数值、存档或公共契约，并将状态改为“已关闭”。

## 7. 关闭结论

- UI 共用按钮主题和主操作层级已完成。
- UI smoke、卡牌多视口布局、macOS headless 启动和格式检查全部通过。
- QA 证据见 `docs/reports/v0.16.0/qa.md`。
- 本版本未修改玩法、数值、存档、core 契约或正式资源稳定 ID。
