## 3. 本轮修复

### S2 存档恢复不可用

- 主检查点损坏但 `.bak` 有效时，旧实现通过普通写入接口恢复。
- 普通写入会先备份当前损坏主档，再因备份校验失败而中止，导致“恢复上次备份”不可用。
- 新实现先读取并校验备份，再写临时恢复档；确认有效后把旧主档移至 `checkpoint.restore-old.json`，最后替换主档。
- 恢复提交失败时尝试把旧主档移回原位，并保留诊断路径。

### S2 恢复入口被错误禁用

- 标题页损坏分支没有把 `backup_available` 传给界面。
- 即使备份存在，“恢复上次备份”按钮仍为禁用。
- 现在损坏状态会明确显示是否有备份，并启用恢复入口；内部英文错误改为中文说明。

### S1 测试档案身份与恢复槽位不一致

- 测试档案写入 `test_checkpoint`，但控制器回到标题后仍检查普通 `checkpoint`。
- 初始测试档案又没有立即建立检查点，首场战斗退出后可能恢复普通档案或没有可继续档案。
- 现在当前档案槽位与测试档案绑定，进入测试档案立即保存初始检查点；普通新游戏切回配置的基础槽位。
- 测试档案从标题可直接进入挑战档案，并可打开挑战修饰选择。

### S2 中文界面泄漏内部英文

- 未知战斗拒绝原因和路线结束原因会显示原始 `reason_code`。
- 状态浮字会显示 `mark`、`weaken` 等内部状态 ID。
- 现在未知原因统一给出中文安全回退，已知状态映射为“标记”“削弱”“流血”“易伤”。

### S2 重复确认非幂等

- 同一退出确认框重复触发 `confirmed` 会重复发出退出意图。
- 现在单次战斗页面只发出一次退出意图，避免重复清理和重复路由。

## 4. 破坏性 QA 方法

测试角色不能以“功能看起来存在”为通过条件。必须选择错误顺序、错误状态和不可恢复边缘：

- 重复/连点：抽卡、出牌、结束回合、退出确认、结算领取。
- 非法阶段：战斗结束后继续出牌、空手牌结束回合、锁定挑战请求开始。
- 空/满资源：券不足、费用不足、满生命治疗、满护盾和最大污染。
- 中断路径：处理中返回、确认框取消、战斗中途退出、页面切换后迟到结果。
- 数据破坏：主档截断、备份损坏、存档版本过高、检查点缺失。
- 恢复与重启：备份恢复后继续、测试档案重启、普通档案不受测试档案污染。
- 重复结算：同一命令结果投递两次、同一胜负快照重复到达、退出确认重复触发。
- 显示边界：全部 16 张卡、全部敌人、未知原因码、未知状态 ID。

## 5. Token 预算制度

产品经理负责阶段预算，不以无目的全量运行或重复读取文档代替判断：

- 单次修改先按目录和修改面选择最小测试集。
- 版本门才执行全部 28 组统一 QA。
- 长日志只读取最终标记和失败上下文，不重复粘贴完整构建输出。
- 同一任务内已读取且未变化的文档不反复读取。
- 角色报告只记录事实、依赖、证据、风险和下一入口，不复制聊天长文。
- 若预算不足以同时完成验证和功能，优先保证安全修复、回归和存档完整性。
