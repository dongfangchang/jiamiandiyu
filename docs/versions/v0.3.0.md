# v0.3.0 单场战斗垂直切片

## 1. 版本信息

- 日期：2026-11-08
- 状态：已关闭（2026-11-08；教学战主链、UI 美术复审和全量回归通过）
- 主题：从新游戏进入一场真实战斗，完成胜负、结算与检查点保存
- 用户价值：先得到可以亲手玩的一小段核心体验，再决定是否扩充内容

## 2. 版本目标

在 1600×900 的 Godot 桌面程序中完成下面这一条真实链路：

```text
启动/新游戏
  -> 固定占卜家初始牌组
  -> 加载正式卡牌、敌人和遭遇数据
  -> 进入一场三列逐张出牌战斗
  -> 打出卡牌、结束回合、显示事件和敌方压力
  -> 胜利或失败
  -> 写入战后检查点
  -> 返回标题并可读取该检查点摘要
```

本版本验证的是“核心是否可玩”，不是完整内容量。抽卡、白天、地图、晋升和完整收藏不进入本版本实现。

## 3. 必须交付

### 3.1 玩法设计

- 按 ADR-0004 把敌方压力改为第 5、7、9 回合开始时增加，并让当回合意图包含加成。
- 提供一份通过 schema 校验的正式首战内容：
  - 8 张占卜家初始/基础卡，来自既有 20 卡稳定 ID 集。
  - 3 个敌人定义。
  - 1 个遭遇定义，至少包含两个敌人以实际使用三列目标。
- 保持冻结命令接口，不新增通用事件总线、目标批量 API 或第二套规则枚举。
- 为每个正式效果提供重复可跑的规则测试。
- 只编辑 `src/core/**`、`src/gameplay/**`、`tests/gameplay/**`、`data/cards/**`、`data/enemies/**`、`data/encounters/**` 和本角色报告。

### 3.2 本地数据层开发

- 与玩法设计确认并冻结卡牌、敌人、遭遇三个正式 schema。
- 通过 ContentPort、BalancePort、RandomPort 装配真实数据，不在适配器里复制规则。
- 应用入口支持“新游戏 -> 第一场战斗”的最小启动流程。
- 战斗结算后调用一次原子保存，至少保存内容版本、序列、固定种子、牌组摘要和上一场结果。
- 启动时读取存档摘要；不支持战斗中途恢复，必须返回明确的检查点语义。
- 不在应用层计算伤害、胜负、抽卡或晋升规则。
- 只编辑 `src/app/**`、`src/infrastructure/**`、`data/schema/**`、`tests/infrastructure/**` 和本角色报告。

### 3.3 UI 设计

- 实现正式启动页、战斗页和结果页的最小 Godot 场景。
- 战斗页只读取 BattleSnapshot/事件，通过 PlayCardCommand、EndTurnCommand 和 QueryCardPlay 显示与提交操作。
- 显示三列敌人、手牌、生命、护盾、灵性、污染、被注视、牌堆/弃牌、意图可见字段和敌方压力。
- 处理 pending、非法目标、资源不足、错误阶段、胜负和事件重放；不得在 UI 重算规则。
- 把 UI 报告中的 `pollution` 统一修正为 `corruption`。
- 只编辑 `src/ui/**`、`scenes/ui/**`、`assets/ui/**`、`tests/ui/**` 和本角色报告。

### 3.4 数值设计

- 把敌方压力参数映射到第 5/7/9 回合时点。
- 使用真实 BattleEngine 和正式首战内容，以固定种子至少跑三种可解释牌序/策略样本。
- 记录胜率、平均回合、压力实际生效次数和最高已应用加成。
- 修正或明确接受谨慎慢速构筑的高胜率；不得直接用硬编码分支掩盖。
- 所有数值仍位于 `data/balance/**`，真实样本只用于调整可玩性，不生成第二份卡牌事实源。
- 只编辑 `data/balance/**`、`tools/simulation/**`、`tests/simulation/**` 和本角色报告。

### 3.5 产品经理与主协调者

- 开局前完成 `art/assets/png/**` 到 `assets/game/**` 的一次受控资源迁移，并更新预览、清单和引用；迁移后不保留同名双份维护。
- 冻结本版本接口和测试入口，监督每项交付是否越权。
- 在真实链路可运行后执行集成验收；任何 S1/S2 问题先定位根因，再决定回滚或替换。
- 所有角色报告写入 `docs/reports/v0.3.0/<role>.md`。

## 4. 冻结接口

本版本以以下接口为唯一实现基线：

- `PlayCardCommand(card_instance_id, target_id?)`
- `EndTurnCommand`
- `QueryCardPlay(card_instance_id, target_id?) -> Playability`
- `BattleCommandResult(accepted, reason_code, events, snapshot)`
- 只读 `BattleSnapshot`：revision、phase、round_number、max_rounds、player、hand、enemies、牌堆计数、敌方压力、outcome。
- `BattleContentPort`、`BattleBalancePort`、`BattleRandomPort`
- 保存检查点仅发生在战斗结算后；不保存战斗中间状态。
- 运行字段统一为 `corruption` 和 `attention`，显示名称不作为主键。

任何接口修改必须先写入角色报告并向产品经理提交请求；`src/core/**` 由玩法设计独占，`data/schema/**` 由本地数据层独占。

卡牌、敌人和遭遇的正式内容由玩法设计维护；其中卡牌自身的效果金额只存在于 `data/cards/**`。`data/balance/**` 只维护全局战斗参数、经济和概率，数值设计可以审核金额但不得建立第二份卡牌定义。

## 5. 依赖顺序与并发

```text
真实性数据与压力时点
  -> schema 与端口装配
  -> 正式战斗 UI 接线
  -> 主链集成
  -> 真实战斗数值采样
  -> 产品验收
```

并行安全规则：

1. 玩法与本地数据层先完成正式数据和装配契约；不得同时编辑同一 schema 或 core 文件。
2. UI 可以使用冻结的假数据视图模型完成静态页面，但在数据端口就绪前不得伪造已集成状态。
3. 数值设计在真实战斗可运行后采样；此前只能更新参数映射，不结论最终平衡。
4. 主协调者最后接入集成测试与资源迁移，不在角色模块内直接打补丁。
5. 最多同时启动三个工作角色；接口变更时暂停下游接线。

## 6. 验收标准

- Godot 无解析错误，资源导入退出码为 0。
- 新游戏可以进入正式数据加载的第一场战斗。
- 玩家能用鼠标完成选牌、选目标、出牌、取消、结束回合。
- 非法操作只得到结构化拒绝和界面提示，不改变状态。
- 第 4 回合无压力，第 5/7/9 回合开始增加 1，当前意图包含加成。
- 胜利、失败、回合上限三种路径至少可由测试覆盖。
- 同一内容版本、根种子和命令序列产生相同事件顺序和最终快照。
- 战斗结束后保存成功；重启后能显示或读取该检查点摘要。
- 不存在战斗中途恢复的误导性 UI；必须明确退出回最近检查点。
- 正式卡牌、敌人和遭遇均通过 schema 校验，稳定 ID 不重复。
- UI 不读取领域内部可变状态、不计算伤害/概率/合法性、不使用 `pollution`。
- 依赖方向符合架构契约，没有绝对路径、循环依赖或重复事实源。
- `docs/reports/v0.3.0/` 记录每个角色的需求、困难、候选方案、解决、验证、风险和下一步入口。

## 7. 明确非目标

- 抽卡抽取、收藏 UI 和保底实现。
- 白天行动、城市地图、非凡事件和完整探索路线。
- “被篡改的讣告”晋升实现。
- 20 张卡全部可玩、6 种敌人全部接入。
- 多途径、多城市、音频、正式美术替换和发布导出。
- 战斗中保存或战斗命令回放 UI。
- 为未来扩展建立插件、通用事件总线或服务器。

## 8. 风险与故障处理

| 风险 | 预防 | 处理策略 |
|---|---|---|
| UI 重新实现规则 | 只消费 snapshot/events；集成测试检查 | 前向修复 UI 适配层，不叠条件分支 |
| 数据 schema 与端口不一致 | 数据层独占 schema，玩法提供语义请求 | 先修正端口契约与适配器；仅在核心流程无法运行时评估回滚 |
| 压力规则只改模拟不改引擎 | ADR-0004 回归测试作为关闭门槛 | 关闭 v0.3.0，不以版本文档掩盖 |
| 资源迁移产生双份引用 | 单一迁移清单，主协调者执行 | 修正路径与清单；若迁移使资源无法加载，再评估定点回滚 |
| 抽卡/晋升提前混入 | 报告候选池，版本关闭前拒绝范围外合并 | 将越权改动移回候选池；保留无关工作 |
| 高胜率自动战斗切片 | 固定种子真实战斗采样 | 保持当前参数并记录风险，下一版本调参 |

最近绿色检查点：`v0.2.0` 接口冻结与模块级测试通过。该检查点只用于运行阻断型故障或用户明确要求时的恢复评估，不能作为普通逻辑、UI 或数值缺陷的默认处理方式。

## 9. 下一版本入口

v0.3.0 已通过并关闭。v0.4.0 主题冻结为“白天身份 + 战后奖励 + 灵界祈愿抽卡 + 简单卡牌升级”的 20—30 分钟单局短循环。v0.4.0 不扩展多途径、多城市和完整晋升。

当前验收定位由 ADR-0007 补充：首场战斗是教学战；正常策略 100% 胜率作为已验证风险保留，不作为完整难度曲线结论。

## 10. 关闭验收

关闭日期：2026-11-08。

通过证据：

- 正式卡牌、敌人和遭遇通过 schema 校验并进入真实战斗。
- 启动、新游戏、正式战斗、胜负、战后保存、返回标题和继续读取链路通过集成测试。
- UI 在 1600×900 实际界面中复审三敌人、专用战斗背景、8 张卡面和状态图标，原型范围通过。
- 正式 PNG 已迁移至 `assets/game/**`；旧 `art/assets/png/**` 与 `art/exports/**` 不再保留。
- 最终回归：玩法 131、基础设施 104、UI 21、应用集成 30、数值合同 33 项通过；主场景 headless 退出码 0。
- `git diff --check` 通过。

已接受风险：

- 首战为教学战，正常策略 100% 胜率，不代表完整难度曲线。
- 美术为程序化矢量原型，精细商业插画留待后续。
- 检查点只允许从战后重新开始同一遭遇，不支持战斗中途恢复。

这些风险不阻塞 v0.3.0 关闭，但必须保留到后续版本记录中。
