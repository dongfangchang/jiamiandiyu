# v0.5.0 短路线与首次序列晋升

## 1. 版本信息

- 日期：2026-11-08
- 状态：已关闭
- 主题：把可重复单场战斗扩展为一次完整的首次晋升路线，目标 15—30 分钟
- 用户价值：让玩家从进入异常调查开始，经过连续战斗、恢复、首领和仪式，真正完成一次序列 9 到序列 8 的晋升

## 2. 版本目标

完成以下真实、可保存、可继续的路线：

```text
启动 / 新游戏 / 继续
  -> 选择白昼身份
  -> 短路线：首战 -> 精英战 -> 休息 -> 首领战
  -> 战后奖励、祈愿与卡牌升级
  -> 被篡改的讣告（30—90 秒轻量仪式）
  -> 占卜家：序列 9 -> 序列 8「小丑」
  -> 保存晋升结果并返回路线结算
```

本版本目标是形成第一次完整章节体验，不扩张到第二条途径、多城市或完整收藏。

## 3. 固定路线

首版路线只做一条，节点固定为：

| 顺序 | 稳定 ID | 类型 | 内容 |
|---:|---|---|---|
| 1 | `route.v050.node.first_hunt` | normal | 复用 `encounter.first_hunt` |
| 2 | `route.v050.node.mirror_pursuit` | elite | 新增镜中猎犬升级遭遇 |
| 3 | `route.v050.node.old_house_rest` | rest | 恢复或降低污染/注视 |
| 4 | `route.v050.node.mirror_baron` | boss | 原创首领「镜厅男爵」 |
| 5 | `route.v050.node.ascension` | ritual | 被篡改的讣告 |

不做分支地图、随机路线、多城市和重复刷图。

## 4. 必须交付

### 4.1 玩法设计

- 实现路线状态机：节点选择、战斗结算、奖励领取、休息、首领、仪式、晋升和路线结束。
- 冻结最小 `RouteCommand`、`RouteEvent`、`RouteSnapshot`、`RitualSnapshot` 和端口职责。
- 复用 `CampaignSession`、`ProgressionEngine` 和 `BattleEngine`，不得复制成长或战斗规则。
- 新增至少一个新的精英遭遇和一个原创首领遭遇。
- 首领战结束且满足条件后进入晋升，不直接创建下一条路线。
- 晋升后局外状态记录序列 8，下一次启动可读取。
- 只编辑 `src/core/**`、`src/gameplay/**`、`tests/gameplay/**`、`data/cards/**`、`data/enemies/**`、`data/encounters/**`、`data/routes/**`、`data/rituals/**` 和本角色报告。

### 4.2 数值设计

- 校准 3 场战斗、1 次休息和首领战的 15—30 分钟节奏；30—45 分钟目标由 ADR-0008 后移。
- 定义休息恢复、首领压力、路线奖励与晋升成本，确保不会因一次抽卡运气形成不可恢复的卡关。
- 对正常、均衡、慢速策略和至少两个身份做真实引擎采样。
- 输出固定种子路线模拟、胜率、平均回合、资源收支和升级/晋升完成率。
- 只编辑 `data/balance/**`、`tools/simulation/**`、`tests/simulation/**` 和本角色报告。

### 4.3 本地数据层开发

- 为路线、休息、仪式和序列状态建立 schema 与适配器。
- 存档版本升级到 3，保留 v1/v2 迁移；无法迁移时保护原档并明确报错。
- 在进入节点、战斗结算、休息、首领结算和晋升提交后建立检查点。
- 继续游戏恢复到最近已确认节点，不恢复战斗中间状态。
- app 只编排用例和场景，不计算路线奖励、晋升条件或战斗规则。
- 只编辑 `src/app/**`、`src/infrastructure/**`、`data/schema/**`、`tests/infrastructure/**` 和本角色报告。

### 4.4 UI 设计

- 新增路线地图、休息节点、晋升仪式和路线结算界面。
- 展示当前位置、已完成节点、资源、污染/注视和可继续点。
- 晋升仪式只展示快照提供的线索、选项、错误提示和结果，不自行判断答案。
- 失败、资源不足、路线结束和存档错误必须有明确恢复路径。
- 对美术候选执行实际界面审稿；美术不得自行验收。
- 只编辑 `src/ui/**`、`scenes/ui/**`、`assets/ui/**`、`tests/ui/**` 和本角色报告。

### 4.5 美术

- 制作短路线羊皮纸地图、休息旧宅场景、原创首领「镜厅男爵」立绘和晋升仪式插画。
- 为「被篡改的讣告」制作无文字证物/印章/三张仪式牌候选。
- 所有候选先进入 `art/**`，由主协调者一次性迁移到 `assets/game/v0.5.0/**`。
- 美术只提交候选与尺寸/授权记录，UI 在实际界面中决定通过或退回。

### 4.6 产品经理与主协调者

- 在实现前冻结路线、仪式、存档和序列字段。
- 检查是否提前引入第二条途径、完整城市地图、多结局章节或复杂谜题。
- 完成路线端到端集成、全量回归、资源迁移和检查点提交。

## 5. 晋升仪式：被篡改的讣告

仪式只做三步，目标时长 30—90 秒：

1. 从三份姓名记录中选择两份与现场线索一致的名字。
2. 将出生、死亡和埋葬三张事件卡排列成正确时间顺序。
3. 选择与占卜结果一致的封印符号。

规则：

- 所有线索均来自当前界面，不要求玩家掌握外部小说知识。
- 玩家可以取消和重试。
- 每次错误增加 2 点污染，不消耗晋升材料。
- 可以消耗 1 点灵性获得一次提示。
- 污染达到上限时晋升中断，路线结算保留已获得的局外收藏和奖励。
- 成功后序列从 9 变为 8「小丑」，记录在持久状态中。

## 6. 冻结接口目标

本版本实现前必须冻结：

- `RouteSnapshot`：当前节点、已完成节点、路线资源、可执行命令和结束状态。
- `SelectRouteNodeCommand`、`ResolveRouteNodeCommand`、`UseRestCommand`。
- `BeginAscensionCommand`、`SubmitRitualStepCommand`、`CancelRitualCommand`。
- `RouteCommandResult`：是否接受、稳定原因码、事件和只读快照。
- `RitualSnapshot`：步骤、当前选项、已选值、污染、提示次数和结果。
- `SequenceState`：途径、当前序列、下一序列名称和晋升状态。
- 所有随机流使用稳定名称，固定根种子可复现。

公共接口由玩法提出，产品经理裁决；`src/core/**` 保持单一负责人。

## 7. 数据与路径

- 路线：`data/routes/v0.5.0/**`。
- 仪式：`data/rituals/v0.5.0/**`。
- 遭遇/敌人：沿用玩法拥有目录，按版本新增文件。
- 存档版本：3。
- 正式资源：`assets/game/v0.5.0/**`。
- 运行路径统一 `res://`，不得使用系统绝对路径。
- 每类事实只有一个定义源，卡牌金额继续只在卡牌定义中。

## 8. 依赖顺序

```text
路线/仪式领域接口
  -> 新遭遇、首领与仪式数据 schema
  -> 存档 v3 与恢复语义
  -> UI 路线/休息/仪式页面
  -> 美术实际界面审稿
  -> app 短路线接线
  -> 全量采样与端到端验收
```

并行边界：

- 玩法先冻结语义，数值和 UI 不自行定义路线或仪式答案。
- 数据层先冻结 schema，再允许 app 接线。
- UI 与美术独立；美术只交候选，UI 完成实际界面审稿。
- 主协调者最后迁移正式资源、接入集成测试并提交检查点。

## 9. 验收标准

- 新游戏能依次完成首战、精英战、休息、首领战和晋升。
- 路线节点状态、资源、污染/注视和已完成位置正确显示并可保存。
- 继续游戏从最近已确认节点恢复，不错误恢复战斗中间状态。
- 每场战斗后能进入奖励与成长流程，且不会重复领奖或重复扣资源。
- 休息至少提供两种明确选择，效果来自领域快照。
- 首领战有独立行为或机制，不是普通敌人仅改生命。
- 三步仪式可取消、重试、提示，失败增加污染且不永久卡死。
- 晋升成功后持久状态显示序列 8「小丑」，重启仍保留。
- 自动化路线时长基线不高于 25 分钟，人工首章目标为 15—30 分钟；不通过虚增生命延长。
- 固定种子下相同命令序列产生相同事件和最终快照。
- UI 不计算伤害、概率、休息效果、晋升条件或仪式答案。
- UI 完成 v0.5 美术实际界面审稿。
- 全部 Godot headless、集成、UI、玩法、数值和主场景检查退出码为 0。
- 没有新增绝对路径、循环依赖、第二套内容事实源或无调用方框架。

## 10. 明确非目标

- 第二条途径或更高序列。
- 多城市、开放世界和自由行走。
- 随机路线、多种章节结局或完整地图编辑器。
- 第二个大型解谜系统。
- 完整 22 卡收藏、商业美术替换和发布导出。
- 战斗中存盘、多人、联网、付费或长期运营。

## 11. 风险与质量门

| 风险 | 预防 | 处理 |
|---|---|---|
| 路线系统重写战斗/成长 | Route 只编排既有用例，接口审查 | 前向修正适配层，不复制规则 |
| 晋升仪式膨胀成长解谜 | 固定三步、界面内线索、可提示 | 超出步骤进入候选池 |
| 存档阶段恢复错误 | run 状态快照、节点边界检查点、迁移测试 | 修正状态机与迁移，不覆盖原档 |
| 首领只是数值放大 | 至少一个独有阶段/行为 | 玩法返回重新设计，不以数值掩盖 |
| 美术与 UI 混合验收 | 独立角色、UI 实机审稿 | UI 退回项由美术候选版本修复 |
| 路线过长拖慢迭代 | 固定三战一休息一仪式 | 优先关闭垂直切片，不临时扩节点 |

## 12. 验收记录

- 关闭日期：2026-11-08

- 玩法：131 项基础、90 项成长、98 项路线测试通过。
- 数据层：150 项基础、67 项路线数据层测试通过；存档 v3 和 v1/v2 迁移通过。
- UI：33 项基础、41 项成长、62 项路线 UI 测试通过；美术实机审稿通过。
- 集成：73 项完整路线测试通过。
- 数值：33 项合同、54 项经济、47 项路线合同测试通过；1200 条固定种子路线完成。
- 主场景 headless 启动退出码为 0，`git diff --check` 通过。
- 自动路线规划中值为 16.45—21.81 分钟，保守—宽松区间为 13.94—24.90 分钟，符合 ADR-0008 的 15—30 分钟首章目标。
- 休息选择已形成真实分布：1200 条采样中包扎 838 次、封锁回声 362 次。
- 首领「镜厅男爵」具备第 3/6 回合双阶段，仪式三步、提示成本、取消重试和序列 8 持久化均已验证。

### 已接受风险

- 这是首次晋升教学路线，正常策略自动完成率仍为 100%，终局生命偏高。
- 快速构筑可能不会触发首领第二阶段。
- 自动路线时长估算不是人工计时；实际操作时若显著超出 15—30 分钟或发现阻断，进入补丁版本修正。
- 程序化矢量美术满足原型识别需求，后续可继续精修。
