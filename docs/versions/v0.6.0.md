# v0.6.0 离线构建与可重复挑战

## 1. 版本信息

- 日期：2026-11-08
- 状态：已关闭
- 主题：让当前完整晋升路线成为可独立启动的离线构建，并增加一次可重复挑战
- 用户价值：不再依赖 Godot 编辑器运行，同时让首次晋升后的卡组和抽卡成长有继续使用的地方

## 2. 版本目标

完成以下用户路径：

```text
双击独立 Windows 构建
  -> 新游戏或继续
  -> 选择身份
  -> 完成首次晋升路线或进入已解锁挑战
  -> 使用身份、收藏、升级和祈愿继续构筑
  -> 挑战结算并保存
```

本版本以“可交付、可重复、可诊断”为主，不增加第二条途径、多城市或开放世界。

## 3. 必须交付

### 3.1 离线构建与运行

- 安装与本机 Godot 4.7.2 匹配的官方导出模板，并记录来源和校验结果。
- 增加 Windows 导出预设，生成独立可执行程序到 `build/windows/`。
- 构建需在项目目录外启动验证，不依赖编辑器、GDScript 缓存、网络或 `.tools/`。
- README 说明启动方式、存档目录、错误恢复和开发启动器的区别。
- 导出构建不包含开发日志、测试夹具、临时缓存和来源不明资源。

- `export_presets.cfg` 与 `build-windows.ps1` 已建立。

### 3.2 可重复挑战

- 完成序列 8 后解锁一条可重复挑战路线；可以复用现有遭遇和卡牌，但不得复制规则或内容定义。
- 至少提供 3 个数据驱动挑战修饰，例如敌人阶段提前、污染压力、奖励限制或牌组约束。修饰必须改变决策，不只提高生命数值。
- 挑战使用现有身份、抽卡、升级、战斗和存档主链；奖励与失败结果可持久化。
- 挑战开始前显示本次修饰、预期资源和退出回最近检查点规则。
- 不新增第二途径；若增加卡牌，优先扩充现有占卜家构筑池。

当前冻结的挑战内容为 `challenge.v060.mirror_echoes`，复用 `route.v050.first_case`，要求序列 8。三个修饰为：

- `modifier.rushed_reflection`：敌人阶段提前 2 回合。
- `modifier.tainted_margins`：初始污染 +4、被注视 +1，每场战斗胜利后再增加 2 污染；正确使用封锁回声可完成，持续包扎会在首领战后触发污染失败。
- `modifier.fractured_deck`：移出所有纸符护持，完成挑战额外获得 1 张占卜券。

挑战领域层、内容端口、规则快照、schema、v4 存档、UI、奖励入账与 app 路由均已完成。`data/challenges/**` 由玩法设计维护，`data/schema/**` 由本地数据层独占。

### 3.3 首轮试玩修复

- 根据实际试玩检查 15—30 分钟节奏、休息二选一、首领第二阶段可感知性和仪式提示。
- 修复只在现有结构上做根因修正；不得用持续加条件或虚增血量掩盖问题。
- 为关键流程补充可重复回归，不依赖手工记忆。

### 3.4 存档与数据

- 当前 `save_version: 4` 已用于普通路线与挑战。
- 若挑战解锁或修饰状态需要持久化，升级 schema 并保留 v1/v2/v3 迁移；不得创建重复事实源。
- 挑战修饰、奖励与内容使用稳定 ID，所有随机流程固定种子可复现。
- 构建版与开发版读取相同内容字段；路径使用 `user://` 和 `res://`。

## 4. 角色任务

### 玩法设计

- 定义挑战解锁、修饰选择、挑战运行和结算状态机。
- 复用 RouteEngine/BattleEngine/ProgressionEngine，避免派生第二套路线规则。
- 提供稳定 commands/events/snapshots，补充挑战规则测试。
- 只编辑自己的领域、正式内容（含 `data/challenges/**`）与报告目录。

### 数值设计

- 设计挑战奖励、修饰风险和构筑压力，确保持续游玩具有变化而不形成不可恢复卡关。
- 运行固定种子挑战采样，比较至少 3 个修饰和两个身份。
- 卡牌金额仍只属于卡牌定义，挑战概率/全局参数才进入 balance。

### 本地数据层开发

- 扩展内容装配、挑战状态保存和必要迁移。
- 配置挑战解锁、检查点和错误恢复；不计算修饰规则或奖励。
- 提供构建版与开发版共享的启动路径。

### UI 设计

- 新增挑战入口、修饰选择、挑战状态和挑战结算页面。
- 只展示领域快照，不计算修饰效果、奖励或解锁条件。
- 对接美术候选并执行实际界面审稿；美术不得自验。

### 美术

- 提供挑战修饰、路线徽记、结算印章和必要背景候选。
- 只编辑 `art/**`，正式资产由主协调者迁移到 `assets/game/v0.6.0/**`。

### 产品经理与主协调者

- 管理导出、构建验证、资源迁移和版本记录。
- 阻止为构建方便破坏模块边界，阻止将测试夹具带入正式构建。
- 在独立构建通过端到端验证后关闭版本。

## 5. 验收标准

- 独立 Windows 构建在无 Godot 编辑器路径注入的情况下启动到主菜单。
- 新游戏、继续、首次路线、挑战、保存、重启继续均可操作。
- 序列 8 完成后解锁至少一条挑战；未解锁状态不能伪造成功。
- 至少 3 个挑战修饰可在固定种子下重放，且产生不同决策压力。
- 挑战失败不会删除局外收藏、升级或已确认奖励。
- 读取损坏存档时显示错误并保留原件，不静默覆盖。
- 所有现有与新增玩法、数据层、UI、数值、集成测试退出码为 0。
- 构建不依赖网络、系统绝对项目路径或未授权素材。
- UI 对 v0.6 美术完成实际界面审稿。
- 没有第二套内容定义、无调用方通用框架或跨层规则渗透。

## 6. 明确非目标

- 第二条途径、更高序列或 22 途径系统。
- 多城市、开放地图、自由行走或联机。
- 付费、广告、账号、云存档和运营系统。
- 完整商业美术替换、配音和复杂动画。
- 为未来未知需求提前建立插件系统、mod 框架或通用事件总线。

## 7. 风险与质量门

| 风险 | 预防 | 处理 |
|---|---|---|
| 导出模板版本不匹配 | 与编辑器 4.7.2 精确匹配并校验 | 更换模板，不修改项目绕过 |
| 构建漏资源 | 在项目外启动并走完整路线 | 修正导出过滤器或资源路径 |
| 挑战变成血量模式 | 修饰必须有机制或决策影响 | 退回玩法重设，不用数值堆叠 |
| 挑战复制 v0.5 规则 | 复用 RouteEngine 与正式内容 | 前向修正适配层 |
| 存档迁移破坏用户进度 | 保留 v1/v2/v3 迁移与原件 | 明确报错并提供备份，不覆盖 |
| 测试夹具进入构建 | 导出排除规则与构建目录检查 | 修正过滤器，重新导出验证 |
