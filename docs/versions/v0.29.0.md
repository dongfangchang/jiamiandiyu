# v0.29.0 序列 8「小丑」最小可玩切片

## 1. 版本信息

- 日期：2026-11-09
- 状态：规划中
- 类型：序列能力与封印物机制切片
- 前一版本：`v0.28.0`，验证中；扮演消化、魔药战利品、动态路线和连续波次已完成最小闭环

## 2. 用户价值

玩家服用小丑魔药后，能在一场短战斗中感受到序列 8 的核心差异：用戏法误导敌人、制造迷惑窗口、以精准投掷完成可靠命中，并在成功闪避后反击。首件封印物提供明确的增益与代价，让晋升不只是数值变化而是新的决策方式。

## 3. 必须交付

1. 建立序列 8 小丑能力标签和规则语义：`trick` 戏法、`misdirection` 迷惑、`precision_throw` 精准投掷、`dodge_counter` 闪避反击。
2. 每类能力至少有一个可由现有卡牌/效果注册表表达的最小运行时用例；UI 只显示玩法层快照和事件，不计算命中、闪避或反击。
3. 设计并接入一张首件封印物，暂定稳定 ID `card.artifact.misleading_pocket_watch`；必须同时定义能力、负面效果、使用条件、来源路径和可重复测试。
4. 首件封印物只能在序列 8 章节战利品或明确剧情事件中获得，不进入无条件随机掉落；重复领取必须安全拒绝或按既有重复规则处理。
5. 延续 v0.28.0 的扮演消化、魔药库存、序列状态和连续波次；新增能力必须在当前序列为 8 且服用记录已持久化时开放。
6. 增加玩法、数据层、UI 和集成回归，覆盖成功、资源不足、目标非法、重复点击、非法序列、战斗波次切换、存档重启和首件封印物重复领取。

## 4. 能力边界

| 能力 | 本版本允许表达 | 本版本禁止表达 |
|---|---|---|
| 戏法 | 1 次短时误导、位置错觉或动作伪装 | 空间传送、无限复制、改变场景结构 |
| 迷惑 | 延迟或改写一次敌方意图，产生可审计窗口 | 永久控制、无条件跳过敌方回合 |
| 精准投掷 | 对已暴露目标造成一次可靠的低序列命中 | 高序列必中、跨场景远程狙杀 |
| 闪避反击 | 在规则层确认成功闪避后触发一次反击 | UI 预判闪避、无限连锁反击 |
| 首件封印物 | 一个增益 + 一个可见代价 + 一个使用条件 | 无代价万能遗物、第二途径能力 |

## 5. 角色任务与依赖

| 角色 | 任务 | 交付 |
|---|---|---|
| 产品经理 | 冻结能力边界、稳定 ID、验收和版本门 | 本文档、版本报告、关闭结论 |
| 玩法设计 | 定义四类能力的状态变化、触发顺序、事件和非法边界 | 玩法报告与最小规则测试 |
| 本地数据层 | 校验序列状态、封印物内容、存档重启和重复领取 | 数据层报告与 schema/加载测试；不得擅自改公共 schema |
| 数值设计 | 为低序列能力和封印物提供可审计的最小参数 | 数值报告/模拟；不把参数写入 UI |
| UI 设计 | 显示能力标签、敌方意图变化、闪避反击结果和封印物代价 | UI 报告、实际窗口截图；不计算规则 |
| QA | 运行专项、旧回归、破坏性路径、窗口和独立构建版本门 | QA 报告 |

依赖顺序：PM 冻结语义 → 玩法/数值定义参数与事件 → 数据层接入内容和持久化 → UI 消费快照/事件 → QA 运行版本门 → PM 关闭。

## 6. 公共接口与数据约束

- 沿用现有 `ProgressionSnapshot`、战斗事件、命令和稳定原因码；如需公共字段必须先在角色报告提出请求并由 PM 裁决。
- `card.artifact.misleading_pocket_watch` 是暂定 ID，正式冻结前不得写入存档或路线内容；若产品裁决更名，必须在版本文档和数据清单中同步一次性变更。
- UI 不计算闪避概率、命中、反击、敌方意图或封印物代价；所有结果来自玩法层快照和事件。
- 不修改存档 schema、RNG 合同、既有卡牌稳定 ID、正式资源稳定 ID 或第二途径规则。

## 7. 验收标准

1. 四类能力各有至少一个可复现的成功用例，事件记录能说明触发、目标和结果。
2. 迷惑只影响声明的单个敌方意图窗口；精准投掷只能作用于规则层已暴露目标；闪避反击只在成功闪避后触发一次。
3. 序列 9、未服用魔药、非法阶段或目标不满足时，四类小丑能力均被拒绝并返回稳定原因码。
4. 首件封印物同时具备能力、负面效果和使用条件；未拥有、重复领取、条件不足和重启恢复路径均有测试。
5. 连续波次与小丑能力组合时，第一波不得提前结束，反击和意图事件顺序可复核。
6. 玩法/数据层/UI/集成专项、旧回归、`git diff --check`、1600×900 与 1100×700 实际窗口截图、独立构建启动全部通过。

## 8. 非目标与风险

- 不新增第二途径、第二章节、复杂召唤物、空间攻击、命运改写或高序列能力。
- 不把封印物做成无条件万能按钮；增益与代价必须同一事实源定义。
- 风险：四类能力引入新的事件竞态。应对：先实现一次性窗口和显式事件顺序，覆盖重复命令与迟到结果。
- 风险：首件封印物稳定 ID 尚未冻结。应对：在正式数据提交前由 PM、玩法和本地数据层共同确认。

## 9. 版本门与关闭条件

- `V029_CLOWN_MECHANICS_OK` 或等价专项必须通过。
- 旧版玩法、成长、路线、牌组、UI、应用、破坏性和存档回归不得出现新增失败。
- 实际窗口必须证明能力标签、敌方意图变化、闪避反击结果和封印物代价可读且不遮挡主要操作。
- 独立构建必须在项目目录外启动成功；版本报告记录截图路径、构建结果、未决风险和下一入口。
- 任一公共接口、存档、稳定 ID 或能力边界未决，版本保持“执行中/验证中”，不得标记“已关闭”。
