# v0.4.0 短循环：身份、奖励、祈愿与升级

## 1. 版本信息

- 日期：2026-11-08
- 状态：执行中
- 主题：把单场教学战扩展成 20—30 分钟可重复的小循环
- 用户价值：第一次让玩家明确感受到“战斗获得资源 -> 抽卡改变构筑 -> 卡牌升级 -> 再战”的成长吸引力

## 2. 版本目标

完成下面一条真实、可保存的短循环：

```text
启动 / 新游戏 / 继续
  -> 选择白昼人格身份
  -> 进入一场正式战斗
  -> 选择战后奖励
  -> 使用占卜券进行单抽或三连祈愿
  -> 将重复卡或材料用于一次卡牌升级
  -> 保存局外收藏、货币与保底进度
  -> 返回白昼或开始下一场
```

v0.4.0 验证的是成长循环，不是完整章节。单次目标游玩时长 20—30 分钟。

## 3. 必须交付

### 3.1 玩法设计

- 定义白昼身份选择、战后奖励、祈愿抽卡、重复卡转化、卡牌升级的最小状态机和命令/事件。
- 首版继续只使用占卜家和现有正式卡牌池，不新增途径。
- 抽卡必须可从固定种子复现；关键战斗卡不能只依赖随机抽取。
- 抽卡只消耗游戏内占卜券或等价资源，不允许真实付费。
- 只编辑 `src/core/**`、`src/gameplay/**`、`tests/gameplay/**`、`data/cards/**` 与本角色报告。

### 3.2 数值设计

- 定义一局白昼行动、战斗奖励、单抽/三连成本、重复卡碎片、卡牌升级成本和保底。
- 确保玩家在一次完整短循环内至少能完成一次可见升级或一次有意义的抽卡决策。
- 提供固定种子经济模拟和真实 BattleEngine 连战采样。
- 只编辑 `data/balance/**`、`tools/simulation/**`、`tests/simulation/**` 与本角色报告。

### 3.3 本地数据层开发

- 扩展存档以保存收藏、卡牌等级、碎片、占卜券、保底计数和身份状态。
- 为抽卡、升级、奖励和身份选择提供应用用例与可复现 RNG 流。
- 保持原子保存、版本迁移、损坏存档保护。
- 只编辑 `src/app/**`、`src/infrastructure/**`、`data/schema/**`、`tests/infrastructure/**` 与本角色报告。

### 3.4 UI 设计

- 新增白昼身份选择、战后奖励、灵界祈愿和卡牌升级界面。
- 战斗、抽卡、升级界面只读取快照并发送命令；不自行计算概率、费用、保底或升级结果。
- 展示抽卡结果、重复卡转化、当前保底提示、升级前后效果和资源不足。
- 对美术候选执行实际界面审稿，并记录通过/退回/仅 UI 适配。
- 只编辑 `src/ui/**`、`scenes/ui/**`、`assets/ui/**`、`tests/ui/**` 与本角色报告。

### 3.5 美术

- 根据 UI 审稿补齐白昼身份、祈愿祭坛、奖励箱/档案和升级反馈所需视觉。
- 保持 `art/ART_DIRECTION.md` 的档案、铜版画、暗金与干血红方向。
- 所有正式候选先进入 `art/**`，由主协调者迁移到 `assets/game/v0.4.0/**`。
- UI 与美术保持独立；美术不得自行标记界面验收通过。

### 3.6 主协调者与产品经理

- 冻结新命令、事件、快照与存档 schema 后再接线。
- 在真实主链可运行后执行短循环集成测试与端到端截图。
- 产品经理检查是否提前引入多途径、地图、晋升或完整收藏。

## 4. 依赖顺序

```text
玩法语义与抽卡/升级命令
  -> 数值经济与保底
  -> schema 与存档迁移
  -> UI 界面与美术审稿
  -> app 路由接线
  -> 端到端短循环与数值复采样
```

并行规则：

- 玩法先冻结状态与命令语义，UI 和数值不抢先定义规则。
- 数值可以提出参数，但卡牌效果金额仍只在 `data/cards/**`。
- 数据层独占 schema；UI 不直接读写文件。
- 美术候选由主协调者迁移，UI 在实际界面中验收。
- 普通缺陷前向修复；只有运行阻断、数据损坏、结构无法安全前进或用户明确要求时评估回滚。

## 5. 冻结接口目标

本版本需要在实现前冻结并记录：

- 身份选择的只读选项与提交命令。
- 战斗奖励选项与领取命令。
- 抽卡请求、抽卡结果事件、保底状态与单抽/三连差异。
- 卡牌升级请求、升级结果、碎片扣除和失败原因。
- 局外收藏/货币/身份/保底快照。
- 抽卡与升级使用的可复现随机流名称。

接口由玩法设计提出，产品经理裁决；`src/core/**` 保持单一负责人。

## 6. 验收标准

- 新游戏可以选择一个白昼身份，并影响至少一项战斗或资源参数。
- 完成战斗后可从至少两个奖励中选择一个，奖励实际写入局外状态。
- 可以执行一次单抽或三连，结果、扣费、保底和重复卡转化一致。
- 可以升级至少一张卡，升级后的效果在下一场战斗中实际生效。
- 抽卡和升级结果在相同种子、相同状态和相同命令序列下可复现。
- 收藏、货币、保底、卡牌等级和身份可保存并在重启后读取。
- UI 不自行计算概率、费用、保底、伤害或升级结果。
- UI 完成对 v0.4 美术候选的实际界面审稿。
- 玩法、数值、基础设施、UI、集成和主场景测试全部退出码 0。
- 没有新增绝对路径、循环依赖、双份内容定义或无调用方的通用框架。

## 7. 明确非目标

- 第二条途径、22 条途径或复杂天赋树。
- 多城市地图、完整白天探索或开放世界。
- 完整晋升仪式和复杂解谜链路。
- 20 卡、6 敌人全部进入主流程。
- 卡池付费、广告、联网、云存档、多人或服务器。
- 战斗动画、正式商业插画替换和发布导出。

## 8. 风险与质量门

| 风险 | 预防 | 处理 |
|---|---|---|
| 抽卡随机导致卡关 | 关键卡确定性获取、保底和固定升级路径 | 前向调整内容与经济，不用隐藏保护规则 |
| 经济与卡牌定义双源 | 卡牌金额只在 `data/cards`，全局概率在 balance | 发现重复定义时停止接线并修正单一来源 |
| UI 自行展示计算值 | 概率、保底和升级结果来自玩法快照 | UI 适配层前向修复，不复制规则 |
| 身份系统膨胀成完整生活模拟 | 首版每种身份只提供一个明确修正 | 超出范围的内容进入候选池 |
| 存档兼容破坏 | schema 版本与迁移测试 | 保留原件，前向迁移，失败时明确报错 |
| 美术与 UI 混合验收 | 两个独立角色、UI 报告结论 | 美术只交候选，UI 实机审稿后才通过 |

## 9. 下一版本入口

v0.4.0 通过后再规划“短路线 + 首次序列晋升”。完成短循环前不得提前实现多段地图与完整晋升。
