# v0.25.0 全流程窄视口与操作可达性收口

## 1. 版本信息

- 日期：2026-11-08
- 状态：执行中
- 类型：UI 适配与试玩可靠性
- 主题：在不同窗口尺寸下让玩家知道哪里可以滚动，并始终找到下一步操作
- 前一版本：`v0.24.0`，有条件关闭

## 2. 用户价值

玩家在战斗、牌组、成长、路线、挑战和晋升页面缩小窗口后，仍能明确知道页面是否还有内容、如何查看被挤出的区域，以及下一步按钮在哪里。v0.25.0 优先收口真实试玩中出现的“画面被截断、看不到按键、点击载入后不知道是否成功”问题，不新增玩法内容。

## 3. 版本范围

### 必须交付

1. 为存在滚动内容的核心页面提供明确的窄视口提示；提示只在内容确实超出当前窗口时出现。
2. 对标题、身份、战斗、路线、休息、奖励、祈愿、升级、牌组、挑战和晋升页面进行 1600×900 与 1100×700 布局检查，确认返回、取消、确认和主要行动可达。
3. 统一 pending、载入、成功、失败和返回中断的可读反馈，避免只显示“已更新”或内部状态。
4. 增加跨页面布局回归和实际窗口证据；发现阻断时先修复根因，不用固定坐标遮盖问题。
5. 保持现有玩法、数值、存档 schema、稳定 ID 和资源路径不变。

### 明确非目标

- 不新增卡牌、敌人、路线、章节、途径、挑战规则或经济数值。
- 不修改存档格式、公共核心契约或玩法状态机。
- 不通过 UI 复制合法性、伤害、概率或胜负计算。

## 4. 首个交付切片

- 战斗页在内容超过窗口时显示“页面内容超出当前窗口 · 上下滑动查看手牌和操作”或对应的完整战场提示。
- 1600×900 下不显示无意义的滚动提示；1100×700 下提示出现且手牌操作仍可通过滚动到达。
- 回归入口：`tests/ui/v025_viewport_guidance_runner.tscn`。

## 5. 角色任务与依赖

| 角色 | 任务 | 交付 |
|---|---|---|
| 产品经理 | 冻结范围、验收口径、处理 v0.24 有条件关闭遗留项 | 本文档与版本报告 |
| UI 设计 | 页面滚动提示、操作可达、状态反馈和多视口适配 | `src/ui/**`、`tests/ui/**`、UI 报告 |
| 玩法设计 | 只读核对阶段和命令语义，不改规则 | 语义核对报告 |
| 数值设计 | 确认无数值改动，继续维护既有模拟基线 | 数值核对报告 |
| 本地数据层 | 核对载入、pending、返回和迟到结果的现有边界 | 数据层核对报告 |
| QA | 运行 1600×900、1100×700、headless、实际窗口和独立构建门 | QA 报告 |

## 6. 验收标准

1. 1100×700 下所有核心页面都能发现继续操作的路径，不能出现永久不可达按钮。
2. 滚动提示只在确有溢出时出现，文字说明与实际滚动方向一致。
3. 牌组载入、战斗操作、奖励领取、祈愿、升级、返回和退出均有明确状态反馈。
4. 1600×900 与 1100×700 的布局回归、headless、格式检查、实际窗口截图和独立构建通过。
5. 不改变玩法、数值、存档 schema、稳定 ID 和正式资源来源。

## 7. 版本门

- v0.24.0 的 1100×700 截图与独立构建证据作为本版本前置遗留项关闭。
- 本版本完成后才进入 v0.26.0 的第一章重复游玩节奏优化。
