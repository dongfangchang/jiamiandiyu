# v0.24.0 美术资源覆盖与一致性强化

## 1. 版本信息

- 日期：2026-11-08
- 状态：规划中
- 类型：美术资产与运行时视觉一致性
- 主题：让完整核心流程使用同一套可追踪、可审稿、可回退的美术资源
- 前一版本：`v0.23.0`，已关闭；祈愿与升级页已补充成长决策信息

## 2. 用户价值

玩家从标题、身份选择、路线、战斗、奖励、祈愿、牌组、挑战到晋升仪式时，应持续感受到同一个“私人神秘学档案”世界。v0.24.0 解决运行时资源覆盖不完整、历史候选未统一归档、页面视觉风格漂移和资源来源难以追踪的问题，让后续美术迭代可以替换单个资产而不改玩法、存档或稳定 ID。

## 3. 版本范围

### 必须交付

1. 建立运行时美术覆盖矩阵：为每个已使用的稳定资源 ID 记录 SVG 源、正式 PNG、尺寸、使用页面、状态（候选/已迁移/已审稿）和来源信息。
2. 对现有 `art/ASSET_MANIFEST.md`、`art/ART_DIRECTION.md`、`assets/game/**` 与 `art/assets/svg/**` 做一次一致性审计；清理同一稳定 ID 的歧义路径，但不删除历史版本资产。
3. 完成高优先级运行时缺口或低质量占位候选：
   - 标题、战斗、路线、休息、奖励、祈愿、牌组、挑战和晋升仪式背景的统一色板与安全区。
   - 20 张正式战斗卡和 3 张身份卡的卡面插画覆盖；继续使用现有 `card.*` 与 `identity.*` 稳定 ID。
   - 现有敌人、首领、状态、资源、路线和挑战图标的风格统一与尺寸复核。
   - 常规、稀有、禁忌卡框和卡背的候选分层；文字、费用和规则信息仍由 Godot 绘制。
4. 以 `art/assets/svg/v0.24.0/**` 保存可编辑源，以 `assets/game/v0.24.0/**` 保存经过迁移的正式 PNG；为每批次生成 manifest 和 contact sheet，禁止把临时导出目录当运行时来源。
5. UI 在实际窗口中审稿：至少覆盖标题、身份、战斗、牌组/挑战、祈愿和晋升页面的 1600×900 与 1100×700 截图，检查裁切、对比度、文字安全区、遮挡和缩小可读性。
6. QA 完成资源路径、稳定 ID、导入、缺失回退、headless、实际窗口和独立构建回归；产品经理只在 UI 审稿结论和 QA 证据齐全后关闭版本。

### 明确非目标

- 不新增卡牌、敌人、路线、章节、途径、玩法规则、数值、抽卡概率或升级费用。
- 不修改存档 schema、公共核心契约、资源稳定 ID、数据主键或运行时状态机。
- 不将文字、费用、规则说明、概率或状态数值烘焙进插画。
- 不引入联网、账号、真实付费、外部素材下载服务或新的第三方依赖。
- 不覆盖或删除历史 `assets/game/v0.3.0` 至 `v0.7.0` 资源；历史版本只读保留。

## 4. 资产优先级与稳定 ID

### P0：运行时完整性与版本门必需

| 资源组 | 稳定 ID 示例 | 使用页面 | 交付要求 |
|---|---|---|---|
| 全局场景 | `scene.title`、`scene.battle.tingen_old_house`、`scene.route.v050.short_road`、`scene.rest.old_house` | 标题、战斗、路线、休息 | 1600×900，保留 UI 安全区，不烘焙文字 |
| 成长场景 | `scene.reward.archive`、`scene.gacha.altar`、`scene.deck.archive` | 奖励、祈愿、牌组 | 1600×900，资源区和操作区对比度通过 |
| 晋升与挑战场景 | `scene.ritual.tampered_obituary`、`scene.challenge.selection`、`scene.challenge.result` | 晋升、挑战选择和结算 | 1600×900，中央信息区留白 |
| 卡牌主体 | 20 个既有 `card.skill.*`、2 个 `card.artifact.*` ID | 收藏、牌组、战斗、抽卡 | 512×400 插画安全区；卡框和文字由 UI 组合 |
| 身份与敌人 | `identity.reporter`、`identity.doctor`、`identity.gravedigger`、既有 `enemy.*` ID | 身份、战斗、挑战 | 身份 512×640；敌人 900×900；主体完整入框 |
| 资源与状态 | `resource.card_shard`、`resource.divination_ticket`、`status.*`、`challenge.*` | 状态栏、奖励、挑战 | 64/96/128/256 规格按用途导出，程序可着色 |

### P1：视觉层级与可替换性

- 常规、稀有、禁忌卡框、`card.back.sealed_omen` 卡背和升级印章 `status.upgrade_1/2/3`。
- 现有 v0.7.0 卡组、路线变体和挑战修饰图标的统一描边、暗金/暗红强调色和透明边距。
- 现有 v0.13.0 四张卡池扩展牌的构图和纸张纹理复核。

### P2：后续候选池

- 其他敌人个体化肖像、更多仪式牌装饰和动效贴图。
- 非核心页面的装饰性纸张纹理、印章变体和图鉴背景。
- 任何新增内容必须先进入后续版本文档，不在 v0.24.0 偷渡新玩法。

稳定 ID 只沿用内容数据和现有清单中的 ID。若发现某个运行时资源没有稳定 ID，角色报告提出 `[REQUEST]`，由产品经理决定是否补充公共注册表；美术不得自行改名或创建与内容数据同名的第二份事实源。

## 5. 角色任务与依赖

| 角色 | 任务 | 允许修改范围 | 依赖与交付 |
|---|---|---|---|
| 产品经理 | 冻结范围、稳定 ID、优先级和关闭门；维护清单与版本文档 | `docs/**`、`art/ASSET_MANIFEST.md` 等协作文档 | 读取 v0.23.0 窗口证据，审核所有角色报告 |
| 美术 | 生成/整理 SVG 候选、导出 PNG、manifest、contact sheet 和来源记录 | `art/**`、`docs/reports/v0.24.0/art*.md` | 遵循 `ART_DIRECTION.md`，不改玩法或正式运行时路径 |
| UI 设计 | 将候选资源接入实际界面并审稿 | `src/ui/**`、`scenes/ui/**`、`assets/ui/**`、`tests/ui/**`、UI 报告 | 只消费稳定 ID；记录通过、返工或仅适配 |
| QA | 资源完整性、导入、缺失回退、截图和独立构建回归 | QA 报告、允许的测试目录 | 依赖美术 manifest 和 UI 审稿证据 |
| 主协调者 | 受控迁移正式 PNG、集成和推送 | `assets/game/**`、构建与集成目录 | 只迁移 UI 通过的候选；保留历史资产 |

依赖顺序：PM 冻结稳定 ID 与 P0 清单 → 美术提交候选和 manifest → UI 实机审稿 → 主协调者迁移正式 PNG → QA 运行版本门 → PM 关闭版本。

## 6. 资源契约与来源要求

- 运行时只引用 `res://assets/game/v0.24.0/**` 或已经冻结的历史正式资源；不引用 `art/**` 源文件作为发布路径。
- 每个候选必须记录稳定 ID、源文件、PNG 路径、尺寸、生成日期、生成方式、提示词或程序脚本、授权和 hash。
- 资产不包含中文文字、数值、规则、按钮标签或水印；界面文字由 Godot 渲染。
- 同一稳定 ID只能有一个当前运行时事实源；旧版本路径保留为历史证据，不作为 v0.24.0 的活动引用。
- 色板遵循 `ART_DIRECTION.md`；单图最多两个强调色，危险使用暗红，身份与秩序使用暗金。
- 资产缺失时沿用现有安全回退或历史正式资源，不允许静默引用任意文件或改变内容数据。

## 7. 验收标准

1. 运行时资源覆盖矩阵覆盖所有标题、身份、战斗、路线、休息、奖励、祈愿、升级、牌组、挑战和晋升页面实际引用的稳定 ID；无缺失、无活动重复事实源。
2. P0 资产全部具备可编辑源、正式 PNG、尺寸记录、manifest 条目和 UI 审稿结论；历史资源未被静默覆盖。
3. 20 张战斗技能卡、2 张封印物卡、3 张身份卡、现有敌人/首领、状态/资源/挑战图标在 1600×900 与 1100×700 实机截图中主体完整、对比度足够、无文字烘焙和操作区遮挡。
4. 标题、战斗、路线、牌组/挑战、祈愿和晋升场景的色板、纸张纹理和边框语言一致；UI 报告明确每批资产为“通过”“需要美术返工”或“仅需 UI 适配”。
5. 资源校验、Godot 导入、headless、当前 UI/玩法/数据层最小回归、实际窗口截图和独立构建全部通过。
6. `git diff --check` 通过；不修改规则、数值、存档 schema、公共契约或稳定内容 ID。

## 8. 风险、回滚点与候选池

- 风险：一次性补齐全部资产导致范围膨胀。应对：P0 先保证运行时覆盖和版本门，P1/P2 只能在剩余时间充足时推进。
- 风险：新 PNG 与历史 SVG 视觉差异造成 UI 返工。应对：所有迁移前先做 contact sheet 和实际窗口审稿。
- 风险：来源或生成记录不完整。应对：manifest 条目不完整的资产不得进入正式运行时目录。
- 回滚点：单个资产按文件粒度回退到上一份已审稿 PNG；不回滚玩法、存档或公共契约。
- 候选池：更多敌人肖像、仪式牌装饰、动效贴图和图鉴背景进入后续版本，不在 v0.24.0 预先实现。

## 9. 关闭条件

产品经理需确认 P0 覆盖矩阵、所有角色报告、UI 实机审稿、QA 版本门和主协调者迁移提交一致；任一 P0 资产缺失、窗口遮挡、来源不明或稳定 ID 漂移，版本保持“验证中”而不关闭。
