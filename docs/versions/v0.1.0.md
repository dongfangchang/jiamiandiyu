# v0.1.0 规划基线

## 1. 版本信息

- 日期：2026-11-08
- 状态：已关闭
- 目标：建立可持续的多智能体开发基线
- 用户可见功能：无；本版本不开始游戏主循环

## 2. 版本目标

把现有对话中的产品方向、协作要求和技术限制转化为可执行的单一事实源。后续角色必须在一个明确产品范围内工作，不能各自决定核心循环、数据格式或 UI 结构。

## 3. 本版本交付物

- 根目录 `AGENTS.md` 协作规则。
- 项目章程、团队协议和架构契约。
- 当前版本指针、版本索引和本版本文档。
- 产品基线 ADR。
- 角色报告、Bug 与版本文档模板。
- 对下一批角色的边界与依赖顺序。

## 4. 对用户需求的完善解释

### 4.1 游戏与消费范围

- 游戏只在本机运行，不建设服务器。
- “后端开发”在本项目中定义为离线本地数据与基础设施层，而不是 Web 服务。
- 抽卡必须依赖游戏内资源；由于是私人项目，不需要支付系统，正式首发也不应默认加入真实付费。
- MVP 的目标是完整闭环，而不是覆盖全部途径和内容。

### 4.2 Bug 修复原则

用户要求中的“出现 Bug 尽量不做增量修改”解释为：

- 先复现和定位根因，避免看到症状就加条件分支。
- 故障模块结构错误时优先回滚、替换或重构。
- 保留最近可运行状态作为回滚点。
- 每个修复有影响面和回归验证，不产生隐性级联。

### 4.3 文档同步

- 每个版本一个版本文件，历史冻结。
- 每个角色在同一版本有独立报告，避免多人同时编辑同一文档。
- 产品经理负责汇总和裁决。
- 采用时间与修改量双触发：30 分钟或 10 个文件，先到者生效。

### 4.4 防止跑偏

- 角色只做本版本明确任务。
- 新点子进入候选池，不能顺手实现。
- 进入正文前必须确认产品经理对接口、数据、路径和版本目标的裁决。
- 共享模块与公共数据不能由多个角色自行定义。

## 5. 角色任务与依赖

### 产品经理

- 维护本版本文档体系。
- 关闭 v0.1.0 后创建 v0.2.0。
- 审核角色报告是否在范围内。
- 不直接实现游戏功能。

### 玩法设计

下一阶段第一优先任务：

- 比较“自动行动 + 玩家部署”与“玩家逐张出牌”的成本与决策深度。
- 提交唯一推荐方案，包含回合状态机、命令、事件、卡牌目标、效果触发顺序、失败/胜利条件。
- 定义白天身份、夜间战斗、抽卡和序列晋升之间的最小闭环。
- 不改 UI、不做数值平衡、不写存档。

### 数值设计

依赖玩法设计的规则草案，但可先准备：

- 首局 10—20 分钟的时间预算。
- 生命、灵性、污染、被注视度的初始值与阈值范围。
- 卡牌成本曲线、敌人数值、局内/局外经济。
- 抽卡概率、保底、重复卡转换和关键卡确定性获取。
- 可复现模拟表结构。

### UI 设计

可先基于章程准备：

- 1600×900 的页面流和低保真线框。
- 白天、地图、牌阵、抽卡、晋升、结算、存档错误页面。
- 视觉状态：可选、不可选、资源不足、目标非法、危险阈值。
- 现有 `art/` 资产的使用位置。
- 不得自行定义战斗规则或数值。

### 本地数据层开发

可先独立准备：

- 目录骨架、上下文注入、内容加载与 schema 校验方案。
- 存档原子写入与迁移策略。
- 可复现 RNG 端口。
- 日志与错误呈现边界。
- 不实现战斗规则、不接 UI 业务。

## 6. 角色并行边界

以下工作可以并行：

- UI 线框
- 数值目标与表结构草案
- 数据层基础设施设计
- 玩法规则对比与状态机草案

以下工作必须等待产品经理汇总：

- 创建共享领域类型
- 固定卡牌效果列表
- 固定存档字段
- 迁移现有美术资源
- 添加第三方依赖
- 确定首条可玩途径

## 7. 验收标准

- 所有强制文档存在且互相一致。
- 根目录代理规则能阻止角色越界修改。
- 每个角色的职责、输入、输出、禁止项明确。
- 版本、报告、Bug 和 ADR 均有固定路径。
- 同步触发条件可执行，不依赖口头记忆。
- 下一版本所需工作按依赖顺序列出。
- 没有声称已实现游戏功能。

## 9. 下一版本入口

建议下一版本为 `v0.2.0`，主题是“规则与接口冻结”：

- 关闭当前开放问题。
- 玩法设计提交完整状态机。
- UI 提交页面流和视图模型需求。
- 数值提交可运行的数据模型与初版表。
- 数据层提交端口、schema 和测试骨架。
- 产品经理形成统一接口表后才允许开始大规模实现。

后续建议路线：

| 版本 | 主题 | 退出条件 |
|---|---|---|
| v0.2.0 | 规则、UI、数据接口冻结 | 接口表通过，跨角色依赖无环 |
| v0.3.0 | 单场牌阵战斗垂直切片 | 可完成一场战斗并可靠结算 |
| v0.4.0 | 局内循环、奖励、存档 | 可连续完成三次遭遇并恢复进度 |
| v0.5.0 | 抽卡、局外升级、晋升仪式 | 形成收集—成长—挑战闭环 |
| v0.6.0 | 内容填充与平衡 | 20—30 分钟完整体验 |
| v1.0.0-rc | 稳定与本地导出 | 无阻断 Bug，存档兼容，独立运行 |

版本号只表示项目内部里程碑，不构成公开发布承诺。
