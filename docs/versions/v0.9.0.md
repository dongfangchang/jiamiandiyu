# v0.9.0 本地试玩反馈与诊断

## 1. 版本信息

- 日期：2026-11-08
- 状态：已关闭
- 主题：用真实本地游玩数据验证节奏、失败原因和构筑体验
- 用户价值：自动记录每轮实际耗时与关键节点，并提供游戏内反馈入口，不联网、不上传

## 2. 版本目标

```text
首次启动 / 继续
  -> 开始一轮路线或挑战
  -> 自动记录开始时间、节点、胜负、升级与挑战结果
  -> 结束后写入本地诊断摘要
  -> 玩家可在设置中查看并填写简短反馈
  -> 反馈与诊断保留在本机，供后续版本改进
```

## 3. 必须交付

### 3.1 本地诊断

- 独立 `user://diagnostics/` 目录。
- 每次启动生成一个独立 JSON 会话文件。
- 记录内容版本、会话开始/结束时间、总时长、路线开始/结束、主要节点、战斗回合、胜负、挑战修饰与结果、抽卡/升级次数和保存错误。
- 不记录个人信息、键鼠内容、网络信息或系统路径。
- 写入失败不得影响游戏运行；诊断采用临时文件校验后替换。

### 3.2 游戏内反馈

- 设置与帮助覆盖层增加“记录试玩反馈”。
- 支持一段自由文本、流程阶段、是否卡关和主观节奏选项。
- 反馈写入同一本地诊断目录，不上传。
- 显示最近一次反馈保存结果。

### 3.3 与应用事件连接

- 应用入口在路线、挑战、战斗、奖励、休息、仪式和胜负处提交轻量事件。
- 应用层只传递稳定 ID 与结果，不复制规则。
- 关闭游戏、返回主菜单和异常结束均尽力完成当前会话摘要。
- 引导、设置和备份操作不改变战斗运行结果。

### 3.4 构建与验证

- 诊断服务有独立文件测试。
- 应用集成覆盖一次完整路线与一次挑战的本地事件记录。
- 设置/反馈 UI 有 headless smoke。
- 独立 Windows 构建重新导出，项目外启动退出码为 0。

## 4. 非目标

- 联网遥测、云上传、账号和隐私分析平台。
- 新增卡牌、敌人、挑战、途径或章节。
- 收集输入内容、截图、剪贴板或用户文件。

## 5. 验收标准

- 每次运行生成时间正确的本地诊断记录。
- 一轮完整路线包含起点、主要节点、总回合、最终结果和实际时长。
- 反馈能够保存并在重启后查看。
- 写盘失败不会中断游戏。
- 不产生网络请求、外部共享或敏感信息。
- 全部现有玩法、UI、集成与独立构建测试通过。

## 6. 下一版本入口

v0.9 获得真实试玩数据和反馈后，再决定第二途径、第二章节或难度扩展。
