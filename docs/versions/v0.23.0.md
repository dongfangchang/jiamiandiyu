# v0.23.0 成长决策闭环

## 1. 版本信息

- 日期：2026-11-08
- 状态：规划中
- 类型：成长流程可理解性
- 主题：让玩家在祈愿与升级之间看懂资源、保底和下一步收益
- 前一版本：`v0.22.0`，已关闭；战后奖励已补充用途与选择时机

## 2. 用户价值

玩家打开白昼档案时，应能回答三个问题：我现在有什么资源、下一次祈愿离稀有保底还有多远、把残页投入哪张牌会得到什么变化。v0.23.0 只整理现有快照和既有规则的表达，减少在祈愿与升级页面之间来回猜测，不改变抽卡、升级或存档规则。

## 3. 范围

### 必须交付

1. 祈愿页补充占卜券用途、单抽/三连成本和稀有保底进度的短说明；说明必须来自现有快照字段，不能由 UI 推算概率或结算结果。
2. 祈愿页在资源不足、保底数据缺失和未知结果时提供可读的安全回退，并保持返回入口可用。
3. 升级页把当前等级、下一等级效果、所需残页、已有残页和差额放在同一张卡片内；满级、未收容和残页不足状态要说明下一步可执行动作。
4. 白昼档案入口与祈愿、升级页使用一致的资源命名和行动文案，避免“残页/碎片/重复回响”混用造成误解。
5. 为上述信息增加 UI 回归，覆盖完整快照、空数据、缺失字段、重复点击和返回中断路径。

### 明确非目标

- 不改变祈愿成本、稀有权重、保底阈值、升级费用或卡牌效果。
- 不新增卡牌、敌人、路线、途径、章节或第二套成长流程。
- 不修改存档 schema、稳定 ID、公共核心契约或离线数据格式。
- 不引入联网、账号、真实货币或后台服务。

## 4. 角色任务与依赖

## 5. 公共接口与数据约束

- 继续消费现有 `ProgressionSnapshot` 和 `ProgressionCommandResult`，不新增公共字段作为本版本前提。
- UI 只读取 `divination_tickets`、`gacha_costs`、`pity_counter`、`rare_pity`、卡牌等级/残页和效果预览等既有只读数据。
- 若发现某个显示语义无法由现有快照准确表达，角色报告必须提出 `[REQUEST]`，由产品经理决定是否进入后续补丁；禁止在 UI 中复制规则或硬编码数值。
- 存档版本、内容版本、RNG 种子和稳定内容 ID 保持不变。

## 6. 验收标准

1. 祈愿页在完整快照下同时说明占卜券用途、单抽/三连成本、保底当前进度和三连结算方式。
2. 祈愿页在零券、缺失成本、缺失保底和未知结果下仍可返回，且不显示虚构概率或错误数字。
3. 升级卡片在可升级时同时显示当前/下一等级效果、已有/所需残页和差额；点击一次只提交一次命令。
4. 未收容、满级和残页不足卡片均给出真实下一步提示，不能把不可执行按钮伪装成可用操作。
5. 白昼档案、祈愿页和升级页的资源名词一致，中文回退完整。
6. 相关 UI smoke、成长流程、headless、格式检查和实际窗口截图全部通过；不得引入现有回归。

## 7. 风险、回滚点与候选池

- 风险：快照字段在异常档案中缺失。应对：采用明确回退文案并保留返回入口，不能用默认数值覆盖存档。
- 风险：说明文字挤压小视口操作区。应对：在 1600×900 和缩小视口做实际截图，优先滚动或折叠说明。
- 风险：不同页面对“残页/重复回响”的称呼不一致。应对：由产品经理冻结词汇表，UI 只引用稳定目录文本。
- 回滚点：v0.22.0 已验证的奖励说明和成长流程测试；若新 UI 造成操作阻断，前向修复失败时回退到该绿色检查点并记录原因。
- 候选池：基于真实试玩记录调整说明优先级；在没有数据前不改经济数值，不扩第二途径或第二章节。

## 8. 关闭条件

产品经理逐项核对验收、角色报告、范围和依赖；QA 提供版本门证据；主协调者确认 `origin/main` 包含版本提交后，才把本文档状态改为“已关闭”，并更新 `docs/CURRENT_VERSION.md` 与 `docs/VERSION_INDEX.md`。
