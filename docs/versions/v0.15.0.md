# v0.15.0 macOS 开发工具补丁

## 1. 版本信息

- 日期：2026-11-08
- 状态：已关闭
- 类型：开发工具补丁
- 主题：补齐 macOS 本地开发与试玩入口
- 用户价值：在 macOS 上可直接打开 Godot 编辑器并启动项目，不需要手动拼接引擎路径。
- 前一版本：`v0.14.0`，已关闭；自适应战斗布局与第四预设

## 2. 范围

### 必须交付

- 提供可执行的 macOS 编辑器启动脚本，定位项目内 `.tools/godot-4.7.2/Godot.app`。
- 提供可执行的 macOS 试玩启动脚本，使用同一项目内 Godot 运行时。
- 启动脚本支持向 Godot 透传额外命令行参数，路径含空格时仍能工作。
- 缺少本地 Godot 时输出明确的安装路径和修复提示，并以非零状态退出。
- README 说明 macOS 启动方式，并保留现有 Windows 入口。

### 明确非目标

- 不修改游戏规则、卡牌、UI、存档 schema、资源稳定 ID 或公共接口。
- 不新增联网服务、插件、包管理依赖或跨平台构建产物。
- 不把 `.tools/`、`.godot/` 或 `build/` 重新纳入 Git 跟踪。

## 3. 角色任务与依赖

- 主协调者：实现 macOS 启动脚本、更新 README，保持 Windows 脚本行为不变。
- QA：验证 shell 语法、脚本缺失依赖时的失败提示、Godot headless 启动退出码，以及工作区没有未授权生成文件。
- 产品经理：维护本版本文档、验收标准和关闭结论。

实现不涉及玩法、UI、美术、数值或本地数据层文件，因此不启动这些角色的并行写入任务。

## 4. 验收标准

1. `zsh -n open-editor-mac.sh` 和 `zsh -n play-mac.sh` 通过。
2. 两个脚本均使用项目根目录的 `.tools/godot-4.7.2/Godot.app`，不写入绝对路径。
3. 在 Godot 存在时，编辑器脚本能启动项目；试玩脚本以 `--headless --quit-after 1` 运行时退出码为 `0`。
4. 临时改名或移除 Godot 入口后，两个脚本都给出可读错误并返回非零状态。
5. `git diff --check` 通过，Windows 启动脚本内容不变；没有修改游戏运行时代码。

## 5. 风险与回滚点

- macOS Godot 包内可执行文件路径可能因发行版变化；脚本应集中检查并在失败时显示实际查找路径。
- macOS Gatekeeper 或文件权限可能阻止首次运行；文档只提示用户授予执行权限，不绕过系统安全策略。
- 本补丁只覆盖本地开发入口；Windows 独立构建仍按 v0.14.0 证据维护。
- 若脚本无法稳定定位编辑器，回滚点为 v0.14.0 提交，保留源码和 Windows 入口。

## 6. 关闭条件

- 上述 5 项验收全部通过。
- QA 报告记录实际命令和结果。
- 产品经理确认范围没有扩展到游戏功能，并将状态改为“已关闭”。

## 7. 关闭结论

- `zsh -n open-editor-mac.sh`、`zsh -n play-mac.sh`：通过。
- 两个脚本在本机 Godot 4.7.2 环境下以 headless 模式启动项目，退出码均为 `0`。
- 在无 `.tools/` 的临时副本中，两个脚本均按预期返回退出码 `1` 并提示缺失路径。
- 额外参数透传、`git diff --check` 和 Windows 启动脚本未修改检查均通过。
- 证据记录：`docs/reports/v0.15.0/qa.md`。

本版本仅补齐 macOS 开发入口，不改变游戏运行时代码、资源、存档或公共接口，现已关闭。
