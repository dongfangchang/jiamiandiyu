# 体验框架：书桌世界（Desk World）

> 状态：**冻结**（ADR-0032，2026-11-24；**ADR-0034 修订**：控件绑定文字、替换即删除、可读性底线）。所有 UI、美术和流程工作都必须符合本文件；违反的交付一律退回。  
> 修改本文件须产品经理开新 ADR。  
> 适用范围：所有现有界面和**后续所有章节**。  
> 实现排期见 `ROADMAP.md` 的 X1–X3。

---

## 0. 为什么需要它（问题陈述）

截至 v0.87，项目同时存在**三套视觉语言**，并且彼此之间是硬切：

| 语言 | 界面 |
|---|---|
| 桌面 3D（v0.84+） | 只有日记 |
| 2D 道具板盖在旧面板上 | 标题（点书时会露出旧面板 = 用户截图） |
| 雨夜平面面板 + Noto Sans | 身份档案（hub）、选路线、牌组、整理卡牌、灵界祈愿、奖励、挑战三屏、结算 |
| 场景图 + 平面面板 | 战斗、休息、仪式 |

流程也有三个问题：
- "继续"直接落进日记，但管理牌组和抽卡要先合上日记回 hub，再"打开日记"。
- "新游戏"要连过 4 个平面屏才见到桌子。
- 思源宋体只用在日记页内，其余界面都是黑体。

根因：每个版本只替换了"当时在做的那一屏"，**从来没有定义过整个游戏是一个什么样的空间**。本文件补上这个定义。

---

## 1. 一句话

**整个游戏发生在同一张书桌上。** 玩家是坐在桌前的非凡者：
- 日记、身份档案、卡匣、祈愿台都是桌上的**物件**。
- 打开一个物件 = 镜头移向它。
- 只有"进入夜间牌阵（战斗/仪式）"才会离开书桌，而且离开和回来都要经过墨迹。

---

## 2. 空间模型

### 2.1 世界（常驻，永不销毁）

`DeskWorld` 是一个常驻的 3D 场景，挂在 `ScreenRouter` 之下，**整局只实例化一次**。它包含：

| 物件 | 位置（俯视桌面） | 对应功能 |
|---|---|---|
| 日记（书） | 桌面中央 | 章节和关卡（现 `diary_chapter_screen`） |
| 身份档案夹 | 左侧 | 身份、序列、资源、当前局状态（现 `identity_screen` 的 hub 模式） |
| 卡匣 + 残页袋 | 右侧 | 出战牌组和卡牌升级（现 `deck_screen` + `upgrade_screen`，合并成一站） |
| 祈愿台（镜、烛、粉笔圈） | 右上 | 灵界祈愿（现 `gacha_screen`），以及晋升仪式（现 `ritual_screen`） |
| 烛台 | 左上 | 系统入口：设置、退出。烛灭 = 回标题 |
| 抽屉 / 值夜者卷宗 | 桌沿 | 挑战模式（现挑战三屏） |

### 2.2 站位（Station）

站位 = **一个镜头位姿 + 一层贴合物件的 2D 内容**。界面不再是"一整屏"，而是"镜头看向某个物件"。

| 站位 ID | 镜头 | 2D 内容挂在哪里 |
|---|---|---|
| `station.title` | 夜色远景，书合着，烛光弱 | 存档摘要和文字菜单写在**书签纸条**上（不是面板，也不是物件热区） |
| `station.desk` | 桌面总览（hub） | 物件本身，加桌角索引卡（文字入口，ADR-0034） |
| `station.dossier` | 推近档案夹，档案夹展开 | 档案页（纸张 SubViewport） |
| `station.diary` | 现在的日记桌视角 | 日记左右页（现有实现） |
| `station.cardbox` | 推近卡匣，匣盖打开 | 卡牌摊开在桌面上；残页袋是升级入口 |
| `station.altar` | 推近祈愿台 | 抽卡 / 仪式的纸面选项与牌面揭示 |
| `station.drawer` | 拉开抽屉 | 挑战卷宗（文件夹样式） |

### 2.3 离桌场景（只有两个）

| 场景 | 是什么 | 视觉要求 |
|---|---|---|
| `scene.battle` | 夜间牌阵 | 必须使用本框架的材质与字体令牌（§5）；背景是"桌布上的牌阵"，不再是雨夜平面 |
| `scene.ritual` | 晋升仪式 | 发生在祈愿台上；X2 以前可以是离桌场景，X2 起改为 `station.altar` 的仪式模式 |

奖励、休息、路线结算、章节结算**不再是独立界面**：
- 奖励：战斗后回到日记，奖励作为**夹进书页的信封/物件**出现在当前开右页，领取后消失。
- 休息：休息节点的那一开，右页就是休息选项。
- 结算：章节最后一开是"终章页"（手写结语 + 完成蜡封）。

---

### 2.4 交互原则（ADR-0034，优先于本文件其他描述）

- **控件 = 文字。** 每个站位的可操作项都是固定位置、可读的文字条目，例如书签纸条上的菜单、索引卡、桌沿书签、蜡封上的字。
- **物件只是画面。** 点物件不触发功能；文字条目悬停或聚焦时，对应物件可以联动提亮或轻推镜头。
- `station.desk` 用桌角的**索引卡**列出「日记 / 档案 / 卡匣 / 祈愿 / 卷宗 / 熄烛」，取代悬停物件出题签。
- **替换即删除。** 新站位上线的同一提交里，删除旧界面的节点、代码和探针；禁止遮挡、隐藏、透明度归零或保留隐形热区。

## 3. 流程（唯一状态机）

```text
TITLE ──继续──▶ DESK(总览) ──自动推近──▶ 当前推荐站位*
  │                 ▲  ▲
  │新游戏           │  └──────────── 返回（任何站位"上一级"都是 DESK）
  ▼                 │
DOSSIER(建档：选身份) ─▶ CARDBOX(选初始牌组) ─▶ DIARY(第一卷第一开)
                    │
DESK ⇄ DIARY ⇄ ⟨墨迹⟩ BATTLE ⟨墨迹⟩ DIARY(奖励夹页)
DESK ⇄ DOSSIER / CARDBOX / ALTAR / DRAWER
任意站位 ──烛灭──▶ TITLE
```

\* **当前推荐站位**由应用层按局面决定，取第一个满足的：
1. 有未领奖励：DIARY（奖励夹页）
2. 牌组未确认：CARDBOX
3. 局内进行中：DIARY
4. 其他：停在 DESK

**关键**：继续时先**落在 DESK 停留约 0.4 秒**，档案夹显示身份和序列一眼，然后镜头自动推近推荐站位。玩家任何时候按"返回"都会回到 DESK，其他物件就在眼前。**不再需要"合上日记 → 换屏 → 打开日记"。**

规则：
- 每个站位只有一个"上一级"，即 DESK；DESK 的上一级是 TITLE。不再有每屏各写一套的 BACK_TARGETS。
- 选路线（`route_select_screen`）合并到 DIARY：书架上 / 桌上的**卷**就是路线。当前只有一卷，选路线就是"翻开第一卷的扉页"。
- 新游戏不再连过 4 个平面屏：建档就是在档案夹里填身份，选牌就是在卡匣里摆牌，然后直接翻开日记。

## 4. 过渡语法（只允许 4 种）

| 编号 | 名称 | 何时用 | 规格 |
|---|---|---|---|
| T1 | 镜头移动 | 同一世界内站位之间切换 | 0.45–0.6 s 缓入缓出的移动加旋转；**不淡出**；目标站位的 2D 内容在镜头到位前 0.15 s 淡入 |
| T2 | 翻页 | 日记内开与开之间 | 前后两开预加载（三开环）；叶片正面 = 当前右页，背面 = 下一开左页；落定只交换引用，不重建 |
| T3 | 墨迹门槛 | 书桌 ⇄ 战斗/仪式 | 蜡封裂开 → 墨晕从蜡封扩散盖满（0.5 s）→ 切场景 → 墨退（0.4 s）；回来时反向，墨退后停在日记当前开 |
| T4 | 烛灭 | 回标题、退出、加载失败 | 烛焰熄灭，0.6 s 暗下；唯一允许全黑的过渡 |

**禁止**：
- 硬切。
- T4 以外的纯黑淡入淡出。
- 一个界面在过渡中露出另一个界面的残留（用户截图里的问题）。
- 过渡期间响应输入（由路由器锁）。
- 在过渡的那一帧同步 `load()` 大纹理：所有可能的下一站资源必须提前请求。

## 5. 视觉令牌（唯一来源：`src/ui/common/theme_tokens.gd`，X1 建立）

| 类 | 令牌 | 说明 |
|---|---|---|
| 字体 | `font.ink`：思源宋体 SC | **所有叙事内文字**：页内、档案、卡名、题签、按钮 |
|  | `font.system`：Noto Sans CJK | 只用于设置、错误详情、调试 |
| 材质 | `mat.wood`、`mat.paper`、`mat.wax.{available,completed,locked}`、`mat.brass`、`mat.ink.{brown,gold,erosion}` | 所有面板一律用纸或木，不使用平面纯色面板 |
| 颜色 | 从材质取样定义：墨褐、金覆写、蜡红、黄铜、侵蚀紫 | 禁止在界面代码里写 `Color("#…")` 字面量 |
| 光 | 烛光为主光源（暖），冷色只用于灵性/侵蚀 | — |
| 控件 | 按钮 = 蜡封、书签、纸签、黄铜钮四种之一 | 禁止原生 `Button` 外观出现在主路径；禁止 `OptionButton` |

**退役**：
- 雨夜平面背景 `ui-canvas-gothic-rain-night.png` 作为界面底：X2 结束后，主路径上不得再出现。
- `UiTheme.add_background` 加面板模块的组合：同上。

### 5.1 可读性底线（ADR-0034 D3）

| 项 | 底线 |
|---|---|
| 3D 世界渲染分辨率 | 窗口物理像素（HiDPI），不得先按逻辑分辨率渲染再放大 |
| 页面 SubViewport | ≥ 1024×1440；mipmap 和各向异性过滤 |
| 屏上字号（1600×900 等效） | 正文 ≥ 20 px，题名 ≥ 28 px，注脚 ≥ 15 px |
| 对比度 | 正文 ≥ 4.5:1，注脚 ≥ 3:1 |
| 阅读姿态 | 书页平面与视线夹角 ≤ 25°（默认镜头调整或悬停推近） |
| 验收 | 1600×900 和 2920×1753 两种窗口各截一张，原尺寸下可读 |

## 6. 章节显示逻辑（后续所有章节通用）

后续新增章节**只能加数据和美术，不能加界面**。

```text
卷（volume）    = 一本日记（书）。data/diaries/<volume_id>.json
 └ 章（chapter）= 卷内一段；以"扉页开"开头、以"终章开"结尾
    └ 开（spread）= 一个关卡节点（1 spread = 1 node）
       ├ 左页：竖幅插画 1260×1770（spread 级美术）
       ├ 右页：题名 ≤10 字 + 笔迹 ≤60 字 + 蜡封
       └ 旁支：kind≠main 的贴条（附在所属开上）
```

| 开的种类 | 左页 | 右页 | 蜡封行为 |
|---|---|---|---|
| 扉页开 | 章名题字版（共用框 + 章插画） | 章引言 | "启"：翻到第一开 |
| 战斗开 | 遭遇场景插画 | 笔迹 | T3 进入战斗 |
| 休息开 | 场景插画 | 休息选项写在右页上（纸签） | 选择后蜡封"已用" |
| 仪式开 | 仪式场景 | 仪式说明 | T1 推近到祈愿台 |
| 终章开 | 章结语插画 | 结语 + 统计（手写体） | "封"：本章完成 |
| 回退开（无日记映射的节点） | 场景图 | 节点名 | 同战斗开（BUG-0038） |

数据约束：
- 新章节必须提供扉页开和终章开。
- 每一开都必须有左页插画；缺图时用回退图，**并且**有测试报告缺图。
- 章节解锁、可进入、已完成状态全部来自玩法快照（ADR-0031），UI 不推导。

## 7. 实现架构（约束 X1–X3）

```text
AppRoot
 └ ScreenRouter
     ├ DeskWorld (常驻 3D，SubViewport)            # 书、档案夹、卡匣、祈愿台、烛台、抽屉
     │    └ StationCamera                           # T1 由它做；站位位姿表在 desk_world 常量中
     ├ StationLayer (2D)                            # 当前站位的 2D 内容（继承 StationBase）
     ├ OffDeskLayer                                 # 战斗 / 离桌仪式（继承 ScreenBase）
     └ TransitionLayer                              # T3 墨迹 / T4 烛灭 / 输入锁
```

- `ScreenRouter` 增加 `travel(station_id)`（T1）、`cross(scene, ink)`（T3）和 `snuff()`（T4）；现有的 `swap()` 只留给离桌场景。
- 每个站位实现 `StationBase`：
  - `station_id()`
  - `camera_pose()`
  - `on_arrive()` / `on_leave()`（可 await）
  - `preload_hints() -> Array[String]`：列出可能的下一站资源，供路由器提前请求
- 日记的 3D 书**并入** DeskWorld（不再有第二个 DeskWorld），`diary_desk_stage` 改为管理"书"这个物件。
- 推荐站位的决定写在应用层的一处函数里（`app/flow.gd`），UI 不判断。
- 路由测试（`screen_router_runner`）扩展为：站位表完整、每个站位的上一级都是 DESK、过渡期间输入锁生效、T1 期间没有同步 `load()`。

## 8. 验收（每个 X 版本都适用）

1. **一致性审查**：截一张"标题 → 继续 → DESK → 推荐站位 → 返回 → 另一物件"的连续截图，每帧都必须是同一张桌子。
2. 守卫：`src/ui` 中没有 `add_background(` 调用（X2 后）；没有 `Color("#` 字面量（`theme_tokens` 除外）；主路径没有黑体渲染的叙事文字。
3. 过渡：除 T4 外，没有任何一帧全黑；没有一帧同时出现两个站位的 2D 内容。
4. 每个新界面需求都必须先回答"它是哪个物件的哪个站位"，答不出来就退回设计。
5. 每个可操作项都是可读文字（ADR-0034 D1）；旧界面已删除，而不是被遮挡（D2）；满足 §5.1 可读性底线（D3）。
