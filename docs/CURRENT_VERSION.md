## 当前冻结规则

- 产品根目录固定为 `G:\guimizhizhu`。
- 单人、离线、Godot 4.7.2、GDScript。
- 本地“后端”只做存档、内容加载、RNG、日志、schema 和应用装配，不建设服务器。
- 抽卡只使用游戏内资源，不允许真实付费。
- 当前仍只使用占卜家；正式战斗卡池为 40 张唯一卡牌。
- 首次晋升固定为占卜家序列 9 -> 序列 8「小丑」。
- 新游戏仅开放「廷根异常调查·第一阶段」；旧五节点原型退出选择入口，底层数据仅保留旧档和挑战兼容。节点数量不再以首版五节点为目标。
- 牌组固定为 8 张唯一卡牌，只能使用已拥有卡牌。
- 同回合非零灵性牌累计连携，阈值和回响效果只从 `battle.chain` 读取。
- 新游戏在身份选择前选择调查路线；后续廷根、贝克兰德、海上阶段仅展示未开放规划，不可启动，不扩第二途径。
- 三名白昼身份必须显示可读的局外或战斗被动。
- 当前牌组和四套预设必须可保存、重启恢复，并实际用于首次路线和挑战。
- 运行字段统一为 `corruption` 和 `attention`。
- UI 只消费只读快照、事件和稳定原因码，不计算伤害、概率、保底、合法性和胜负。
- 美术与 UI 是独立角色；美术提交候选，UI 在实际界面审稿，美术不得自行验收。
- 普通缺陷默认前向根因修复；仅运行阻断、数据破坏、结构无法安全前进或用户明确要求时评估回滚。
- BUG-0004 至 BUG-0018 未全部关闭前，不得开发第二途径、第二章节或新增内容。
- S3 显示问题可进入候选池或小型补丁，不得冻结不相关角色的功能开发。
- 按钮禁用只有在没有合法下一步、无法返回/取消且形成永久死锁时才按 S1 处理。
- 发布必须同时通过自动化、headless、实际窗口与截图验收；退出码为 0 不代表真实交互通过。
- 测试必须包含重复、非法阶段、中断、损坏存档和重复结算等破坏路径。
- 日常迭代按修改面选择最小测试集，只有版本门运行全量 QA。
- 产品经理负责 Token 预算，禁止重复读取相同长文档和重复粘贴长日志。
- 每个版本新建独立文档，历史版本不覆盖。
