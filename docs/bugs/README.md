# Bug 记录规则

## 严重度

| 级别 | 定义 | 处理 |
|---|---|---|
| S0 | 数据丢失、无法启动、存档被破坏 | 停止开发，回滚绿色检查点 |
| S1 | 核心流程不可完成、规则结果错误 | 停止相关功能扩展，根因修复 |
| S2 | 明确错误但有临时绕过 | 当前版本内修复并记录 |
| S3 | 表现、文案或低频问题 | 排入合适版本 |

## 流程

1. 创建 `BUG-xxxx.md`。
2. 记录可重复步骤、实际结果、期望结果和影响。
3. 定位根因，不接受仅描述症状。
4. 比较回滚、替换/重构和最小根因修复。
5. 检查共享契约、数据 schema、存档和资源路径的级联影响。
6. 编写回归验证。
7. 修复后记录验证结果和剩余风险。

## 禁止

- 在错误结构上连续叠加条件分支。
- 用静默默认值掩盖损坏数据。
- 没有回归验证就关闭 S1/S2。
- 修复一个模块时顺手修改无关行为。
- 覆盖旧存档来“解决”迁移问题。

新缺陷使用 `docs/templates/bug.md`。
