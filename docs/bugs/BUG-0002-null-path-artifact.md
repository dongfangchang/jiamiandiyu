# BUG-0002：错误的 shell 重定向生成 `$null` 文件

- 版本：v0.2.0
- 严重度：S3
- 发现角色：产品经理
- 负责人：主协调者
- 状态：已关闭

## 症状

项目根目录出现内容为 PowerShell 命令错误的普通文件 `$null`，其文件名来自被 Bash 当作普通字符串的重定向目标。

## 复现步骤

1. 让 `functions.exec_command` 使用 Bash。
2. 提交包含 PowerShell 语法 `2>$null` 的命令。
3. Bash 将 `$null` 当作当前目录中的输出文件。

## 实际结果

项目根目录创建无意义文件 `$null`。

## 期望结果

PowerShell 命令始终由 PowerShell 执行，错误流不应生成项目文件。

## 影响范围

- 工作区目录污染。
- 可能被误提交进 Git。
- 不直接影响游戏运行时。

## 根因

执行 shell 与命令语法不匹配。项目同时使用 PowerShell 与 Bash 工具调用时，没有强制命令执行器一致。

## 候选修复

| 方案 | 影响面 | 风险 | 选择 |
|---|---|---|---|
| 只删除文件 | 当前工作区 | 同类问题会再次发生 | 否 |
| 在 `.gitignore` 忽略 `$null` | Git | 隐藏问题，目录继续污染 | 否 |
| 强制命令 shell 与语法一致并增加最终杂项检查 | 工具流程 | 需要每次工具调用遵守 | 是 |

## 级联检查

- 共享契约：无。
- 数据 schema：无。
- 存档格式：无。
- 资源路径：无。
- 游戏运行时代码：无。

## 回归验证

- 删除当前 `$null` 文件。
- 后续 PowerShell 命令只使用 `shell: powershell`。
- 提交前使用 `git status` 检查未知根目录文件。

## 最终结果与剩余风险

已确认目标仅为 70 字节的错误输出文件，并通过精确绝对路径删除。后续工具调用必须保持 shell 与语法一致；此工作流错误不应以忽略规则掩盖。
