# BUG-0003：升级到 v4 后旧备份被误判损坏

## 状态

- 版本：`v0.6.0`
- 严重度：S2
- 状态：已修复
- 发现角色：本地数据层开发

## 症状

存档从 v3 升级到 v4 后，第一次覆盖同一存档槽时，旧 v3 备份被当前 v4 schema 直接校验，错误报告为损坏或不可恢复。

## 复现

1. 准备有效 v3 主存档。
2. 启动 v0.6 数据服务并写入 v4 检查点。
3. 检查迁移过程中生成的旧版本备份。
4. 旧逻辑直接按 v4 schema 校验 v3 备份，返回失败。

## 期望

备份保留其原始 `save_version`，验证时必须先按迁移链升级到当前版本，再执行当前 schema 与不变量检查；迁移或校验失败时保留原件并明确报错。

## 根因

`AtomicSaveService` 的备份验证沿用了“当前 schema 直接校验”的路径，没有复用 v3 → v4 的迁移链。

## 修复

- 备份验证先识别保存版本，再按 v1 → v2 → v3 → v4 显式迁移。
- 仅对迁移后的文档执行当前版本 schema 和不变量校验。
- 保持临时文件、原子替换、原件保护和备份可恢复语义。

## 回归

- `tests/infrastructure/challenge_backend_runner.gd`
  - v3 主档可迁移并保存为 v4。
  - v3 备份通过迁移链验证。
  - 损坏档不覆盖原文件并报告安全错误。
- 最终基础设施测试：150 项通过。
- 挑战后端测试：65 项通过。

## 剩余风险

跨进程强制终止发生在主文件替换与备份切换之间时，严格事务保证仍受文件系统限制；当前实现保留可恢复备份并明确报告失败，不伪报保存成功。
