# BUG-0001：存档版本迁移前执行了当前 schema 校验

- 版本：v0.2.0
- 严重度：S2
- 发现角色：本地数据层开发
- 负责人：本地数据层开发
- 状态：已关闭

## 症状

旧版本存档在进入迁移器前被当前版本 schema 拒绝，使可迁移存档表现为损坏或不兼容。

## 复现步骤

1. 准备一个旧 `save_version`、字段结构尚未升级的合法存档。
2. 注册对应的版本迁移器。
3. 通过原子存档服务读取该文件。
4. 观察读取在迁移前返回当前 schema 校验失败。

## 实际结果

迁移流程没有执行，旧档被当前版本校验拦截。

## 期望结果

先解析 JSON 和读取基础版本字段，再调用目标版本迁移，迁移完成后执行当前 schema 与不变量校验。

## 影响范围

- 旧版本存档升级。
- 后续新增字段时的兼容路径。
- 备份恢复与用户进度保留。

## 根因

加载顺序错误：当前版本字段校验被放在版本识别与迁移之前，使旧结构无法进入迁移阶段。

## 候选修复

| 方案 | 影响面 | 风险 | 选择 |
|---|---|---|---|
| 在旧版本上叠加校验例外条件 | 校验器与迁移器 | 兼容分支累积，后续版本难维护 | 否 |
| 跳过所有校验直接迁移 | 存档安全 | 损坏数据可能进入领域层 | 否 |
| 重构为解析 -> 迁移 -> 当前 schema 校验 | 单一加载管线 | 需要逐版本迁移回归 | 是 |

## 级联检查

- 共享契约：无修改。
- 数据 schema：本修复不改变字段，只修正校验时点。
- 存档格式：不改变当前版本格式。
- 资源路径：无影响。
- UI：错误分类保持不变。
- 玩法：无影响。
- 数值：无影响。
- 本地数据层：加载管线已调整。

## 回归验证

- 缺失迁移器时必须明确返回 `migration_missing`。
- 迁移成功后返回 `migrated=true`，并完成当前版本校验。
- 迁移失败或迁移后校验失败时不得覆盖原存档。
- v0.2.0 基础设施测试通过。

## 最终结果与剩余风险

已按根因重构加载顺序，没有增加旧版本字段例外分支。剩余风险是后续每个存档版本都必须提供并测试对应迁移器。
