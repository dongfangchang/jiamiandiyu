## 本版本目标

让核心流程使用同一套可追踪的档案式美术语言，并为每个运行时稳定资源 ID 建立源文件、正式 PNG、使用页面和审稿状态。版本不新增内容和规则，只完善资产覆盖、来源记录、迁移和实际界面质量。

## 困难与方案

| 困难 | 候选方案 | 最终选择 | 理由 | 风险 |
|---|---|---|---|---|
| 历史版本资产多，活动引用不易确认 | 直接重命名并覆盖旧资源；或建立 ID 覆盖矩阵 | 建立 v0.24.0 矩阵和版本化活动路径 | 保留历史证据，避免稳定 ID 漂移 | 需要 QA 校验路径 |
| “全面完善”容易变成无限美术清单 | 一次性制作所有候选；或按 P0/P1/P2 分层 | P0 以运行时覆盖为发布门，P1/P2 进入候选池 | 先保证可玩流程一致，再扩展装饰 | P1/P2 可能延后 |
| 美术自审无法证明实际界面可用 | 仅查看 contact sheet；或交 UI 实机审稿 | UI 在 1600×900、1100×700 逐页审稿 | 裁切、对比度和遮挡只能在实际界面确认 | 审稿可能退回候选 |
| 资产来源记录不完整会阻断迁移 | 先迁移后补记录；或 manifest 完整后迁移 | manifest 完整是正式迁移前置条件 | 便于回溯和后续替换 | 初期进度较慢 |

## 风险与未决问题

- P0 资产矩阵尚未由美术建立，当前不能宣称资源覆盖完成。
- v0.7.0 和 v0.13.0 资产需由 UI 确认当前运行时页面中的裁切、对比度和稳定路径后，才能决定是否迁移到 v0.24.0 活动目录。
- 未经 UI 实机通过和 manifest 完整记录的候选不能进入正式运行时路径。
- 用户要求“全面完善”仍受 P0/P1/P2 分层约束；新增内容或玩法必须另立版本。
