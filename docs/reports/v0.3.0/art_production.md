## 困难与候选方案

| 困难 | 候选方案 | 最终选择 | 结果 |
|---|---|---|---|
| 三类敌人共用提灯追猎者 | 只换颜色；复用背景叠加；制作独立轮廓 | 制作三张独立敌人 | 轮廓可区分 |
| 战斗背景透出晋升文字 | 更高暗化；纯色背景；独立战斗场景 | 独立 1600×900 无文字背景 | 语义冲突消除 |
| 完整卡牌文字被烘焙后缩小不可读 | 缩小整卡；裁切卡中央；制作无文字插画 | 制作 8 张独立 512×400 插画 | 可由 UI 单独排版 |
| 清单路径基准不清 | 一律项目根；一律 art 根 | 统一以 `art/` 为基准 | 渲染流程已按该规则通过 |
| Edge 对 64×64 视口截图挂起 | 强制 64×64；程序裁剪；生成 atlas | 512×512 渲染后裁切 | 12 个图标完成 |

## 交给 UI 的复验项

1. 在实际 1600×900 战斗页中检查三敌人是否能在约 205—240 px 高度下靠图片和名称区分。
2. 检查新战斗背景与 HUD、三列面板、手牌面板的对比度，确认没有文字或仪式语义透出。
3. 检查 8 张卡面在 100×80 左右缩略时是否仍能识别核心符号。
4. 检查状态图标在 24—32 px 显示时是否需要加底、描边或增大内部图形。
5. UI 只做遮罩和不改业务逻辑的适配；若需改画面构图或轮廓，退回美术。
