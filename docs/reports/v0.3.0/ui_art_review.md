## 总体结论

现有资产已经形成一致的神秘档案风格：旧纸、墨黑、暗金、干血红的使用克制，标题页和结果页的视觉层级清楚。作为私人原型，美术方向通过。

当前不能直接视为“可交付战斗视觉”，主要原因是战斗页仍使用晋升仪式背景、三种敌人共用同一张图、手牌没有卡面插画。它们会显著降低战斗辨识度和卡牌游戏的核心观感。

## 必须返工的美术需求

### P0：三张独立敌人插画

为以下稳定 ID 各制作一张独立 900×900 透明或深色背景插画：

- `enemy.weeping_tenant`：哭泣的房客，湿发/门缝/人形轮廓为主要识别符。
- `enemy.candle_moth`：烛焰飞蛾，翅膀和烛火形状为主要识别符。
- `enemy.mirror_hound`：镜中猎犬，犬形与碎裂镜面为主要识别符。

规格：

- 主体占画布 55%—70%，居中，战斗裁切到约 205—240 px 高度后仍能识别。
- 不在图片中烘焙敌人名称、生命值或意图。
- 保持暗金、骨白、干血红、冷雾灰的统一色板。
- 三张图必须在缩略图尺寸下仅看轮廓也能区分。

### P0：独立战斗背景

新增 1600×900 战斗专用背景，主题为“廷根旧宅的夜间房间或街道”，不能包含以下文字：

- 战斗标题。
- “晋升试炼”。
- “PATHWAY ADVANCEMENT”。
- 任何需要缩小时阅读的长句。

画面中央和右上角保留低细节区域作为敌人与状态栏衬托，底部约 30% 保持可被手牌面板遮挡的克制纹理。

### P1：8 张独立卡面插画

为 v0.3.0 的 8 个卡牌 ID 提供 512×400 的无文字插画裁切：

```text
card.skill.ink_dart
card.skill.paper_guard
card.skill.calm_breath
card.skill.focus
card.skill.insight
card.skill.omen
card.skill.whisper
card.skill.second_look
```

图片不得包含卡名、效果、数值、边框或中文小字。卡名、费用和规则文本继续由 Godot 渲染。缩到约 100×80 时至少保留一个清晰的视觉符号。

### P1：独立状态图标

将 `status-sheet.png` 拆成 12 个 64×64 单图，或提供明确的 atlas region 映射。UI 目前不应一次加载整张 1200×800 图标表来显示一个小状态。

## 仅需 UI 适配的问题

- 战斗页暂时改用标题背景并提高到 0.86—0.9 暗化，避免晋升仪式标题透出；正式战斗背景到位后替换。
- 手牌卡位在不加入新图前可先显示统一的卡框缩略占位，正式插画接入后再替换纹理。
- 状态栏的次级文字对比度略低，建议提高一档亮度；这是 UI 可读性调整，不需要美术重画。
- 三种敌人在图片补齐前必须有清晰显示名和不同的列状态标识；不能让玩家仅凭重复图片判断敌人。

## 困难与候选方案

| 困难 | 候选方案 | 当前选择 | 原因 |
|---|---|---|---|
| 只有一张敌人图却已有三种敌人 | 一图复用；按类型改变颜色；补三张独立图 | 短期可临时复用，正式内容补三张图 | 颜色叠层不能替代轮廓辨识 |
| 卡面文字已烘焙 | 直接缩小整卡；裁切中央；补独立插画 | 补 512×400 无文字插画 | 缩小整卡会让中文和数值不可读 |
| 仪式背景被战斗页复用 | 继续提高暗化；换纯色；新增战斗背景 | 短期 UI 适配，正式补背景 | 纯暗化仍可能露出冲突文字 |

## 风险

- 三列敌人共用图片会直接影响目标选择与战斗可读性。
- 完整卡牌图片把文字烘焙在图像里，缩小后会形成不可读的双重文字。
- 当前截图来自手动快照，正式敌人名称、生命和意图数据还需接入真实 `BattleSnapshot` 后再复查。
- 本审稿没有修改 `art/` 源文件，也没有声称退回项已经修复。
