## 本轮监督决定

- 普通逻辑、UI 和数值缺陷采用前向根因修复或局部替换。
- 只有运行阻断、数据破坏、无法安全前进的结构性错误或用户明确要求时才允许回滚。
- 所有回滚必须由产品经理记录原因、目标检查点、影响文件和恢复范围。
- 任意接口、schema 或资源路径变化先进入角色报告，不得静默修改。
- `data/cards/**`、`data/enemies/**`、`data/encounters/**` 已明确划归玩法设计。
- 卡牌效果金额只在正式卡牌定义中保存；`data/balance/**` 只保存全局战斗参数、经济和概率。数值设计负责审核，不维护第二份卡牌定义。

## 并发安排

1. 玩法设计与本地数据层先完成正式内容 schema、端口映射和压力规则。
2. UI 按冻结快照完成启动、战斗和结果页，不自行计算结果。
3. 主协调者执行唯一一次资源迁移和最小集成接线。
4. 数值设计在真实 BattleEngine 上采样，不建立第二份卡牌事实源。
5. 产品经理在集成后检查范围、依赖、测试和版本验收。

## 困难与候选方案

| 困难 | 候选方案 | 当前决定 | 风险 |
|---|---|---|---|
| 集成失败时容易整体回滚 | 全部回滚；默认前向修复；按模块定点恢复 | 默认前向修复，仅运行阻断型故障评估回滚 | 需要更准确的根因定位 |
| 多角色共享工作区 | 自由并行；串行开发；目录所有权并行 | 按目录所有权并行，共享契约单负责人 | 接口变化仍需及时同步 |

## 风险与未决项

- 教学战正常策略为 100% 胜率；已由 ADR-0007 接受为教学范围，不代表完整平衡。
- UI 新资产复验已关闭；最终截图确认专用战斗背景、三敌人和手牌缩略可辨识。
- 当前只有一场正式遭遇，不能据此评价 20 卡、6 敌人或多遭遇成长曲线。
- 继续入口从战后检查点重开同一遭遇，不恢复战斗中间状态。
- 8 张卡面、12 个状态图标进入实际 UI 后仍需检查缩略可读性和遮挡。
- 正式 PNG 已迁移到 `assets/game/**`，最终提交前需确认没有旧目录双份引用。
