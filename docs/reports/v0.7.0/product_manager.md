# v0.7.0 / 产品经理

## 状态

- 版本：`v0.7.0`
- 角色：产品经理
- 任务：卡组构筑与第二挑战的范围、依赖和验收
- 状态：规划已完成，等待角色实现
- 最后更新：2026-11-08

## 版本目标

让抽卡、升级和收藏直接服务于出战牌组选择，并为完成 `v0.6.0` 挑战的玩家提供第二挑战。

## 已冻结

- 首版牌组为 8 张唯一卡牌，只能使用已拥有卡牌。
- 初始拥有至少 8 张卡，首次进入构筑即有合法牌组。
- 支持三套本地牌组预设与恢复初始牌组。
- 当前牌组必须在首次路线和挑战战斗前生效。
- 第二挑战要求序列 8 且完成 `challenge.v060.mirror_echoes`。
- 第二挑战复用现有 RouteEngine/BattleEngine/ProgressionEngine/Checkpoint，不复制流程。
- 新增卡牌至少 8 张，优先复用已注册 effect；卡牌效果与金额只存在于 `data/cards/**`。
- 新的存档字段进入 v5，并保留 v1/v2/v3/v4 迁移。
- UI 与美术保持独立，UI 完成实际界面审稿后美术资产才算通过。

## 依赖顺序

1. 玩法冻结 DeckCommand/DeckSnapshot、卡组合法性、第二挑战解锁和路线覆盖语义。
2. 数值审核新增卡牌、三套牌组方向和第二挑战修饰。
3. 数据层冻结卡池/牌组 schema、v5 迁移和只读摘要。
4. UI 与美术并行制作；UI 审稿美术。
5. app 接入牌组选择、第二挑战和完整保存恢复。
6. 全量回归、独立 Windows 构建和项目外启动验收。

## 当前风险

- 新增卡牌可能造成卡池与数值双源，必须保持 `data/cards/**` 为唯一卡牌事实源。
- 牌组构筑若只有唯一最优解，会让抽卡和升级失去意义，需要真实引擎采样。
- 第二挑战若复制路线规则，会造成存档和状态机分叉。
- 人工试玩尚未执行，任何体验问题进入前向修复或补丁版本，不直接回滚已验证功能。

## 下一步

先派发玩法与数值冻结任务，再允许数据层 schema、UI、美术和 app 接线并行。
