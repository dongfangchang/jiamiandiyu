## 用户价值

玩家现在可以完成：

```text
启动/新游戏/继续
  -> 选择白昼身份
  -> 真实战斗
  -> 二选一战后奖励
  -> 单抽或三连祈愿
  -> 重复卡转碎片
  -> 升级卡牌
  -> 保存并进入下一场
```

## 角色需求、困难与解决

| 角色 | 需求 | 困难 | 解决 |
|---|---|---|---|
| 玩法 | 身份、奖励、抽卡、重复卡与升级统一领域 | 卡牌升级必须真实进入下一战；工具牌不可升级却出现在池中 | 内容端口装饰器；把 `second_look` 移出祈愿池并增加池不变量 |
| 数值 | 一个循环内可完成有意义成长 | 多条路线经济差异、重复卡池边界 | 固定种子 1000 路线模拟；将可升级卡池与正式卡池分开断言 |
| 数据层 | 扩展存档并保持旧档可读 | v0.3 存档缺少收藏与保底字段 | save_version 2 和显式 v1 -> v2 迁移 |
| UI | 四个新页面且不复制规则 | snapshot/result 字段多、pending 与重复点击 | 只读快照、命令信号、稳定原因码和 41 项成长 UI 测试 |
| 美术 | 身份、祭坛、奖励、升级视觉 | 独立角色，不能自行验收 | UI 在实际界面审稿，v0.4 候选通过原型范围 |
| App/主协调 | 串联完整短循环 | 战斗、奖励、祈愿和升级阶段路由不同 | CampaignSession + app_controller 状态路由与 39 项集成检查 |

## 风险

- 当前仍重复进入同一首战，内容连续性有限。
- 教学战难度不代表完整成长曲线。
- 程序化美术精细度有限。
- 多行卡牌描述增加时需要重新检查手牌布局。

## 关闭结论

v0.4.0 通过验收并关闭。下一版本在现有主链上增加短路线、休息、原创首领和首次序列晋升，不重写或回退本版本能力。
