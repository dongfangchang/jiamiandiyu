## 开发顺序

1. 导出模板与 Windows 构建先行，确保当前版本已成为真正可交付的离线程序。
2. 玩法定义挑战解锁、修饰和结算语义。
3. 数值设计挑战压力与奖励，数据层冻结必要 schema。
4. UI 与美术分离生产，UI 必须实机审稿挑战相关美术。
5. app 接入挑战入口、路线和检查点，完成独立构建端到端验证。

## 风险

- 构建资源遗漏可能只在导出后出现，不能只依赖编辑器运行测试。
- 挑战若只提升敌方生命，会重复 v0.5 的内容压力问题。
- 自动路线时长仍不能替代实际人工试玩；用户首轮反馈优先进入补丁修复。
