## 困难与方案

| 困难 | 候选方案 | 最终选择 | 理由 | 风险 |
|---|---|---|---|---|
| 公共 schema 尚未冻结 | 由数据层自建 schema；只做通用文件与随机能力；等待 ADR | 先做不依赖领域字段的通用能力 | 避免第二数据源和提前冻结 | 与玩法集成需下一阶段完成 |
| 加载迁移时完整校验顺序错误 | 为旧版本增加例外分支；拆开解析与校验阶段；回滚全部功能 | 拆成 JSON 解析 → 版本迁移 → 当前版本完整校验 | 直接修复结构性根因，不堆积兼容分支 | 迁移器仍需逐版本回归 |
| Godot 文件替换没有跨平台原子 swap | 直接覆盖主档；先删除主档；临时文件 + 备份 + 失败恢复 | 临时文件 + 备份 + 失败恢复 | 避免在写入或验证失败时破坏已有主档 | 进程在删除与重命名之间强制终止时，主档可能暂时缺失，但备份仍可用 |
| 外部数值文件尚未冻结正式 schema | 在基础设施内写死字段；不校验；只校验顶层 `schema_version` | 只校验通用版本字段，正式 schema 等待 ADR | 当前不复制数值事实源 | 正式字段错误要到 schema 接入后才能发现 |
| Godot 首次导入时 `class_name` 缓存尚未建立 | 依赖全局类名；显式 preload；把类注册写进测试入口 | 基础设施模块显式 preload | 冷启动和独立测试更可靠 | 同模块重复常量需避免循环引用 |
| `SeededRandomStream` 不能作为 `BattleRandomPort` 参数 | 修改 core 端口；让玩法直接依赖具体流；基础设施适配 | 新增 `BattleRandomAdapter` 包装命名流 | 保持依赖方向与冻结签名 | 每个战斗随机用途需要明确流名 |
| 适配器静态工厂引用自身类名 | 建全局工厂；在适配器内自加载；应用层实例化 | 应用层装配 | 避开类缓存顺序和循环 preload | 新增端口时必须同步更新应用装配 |
