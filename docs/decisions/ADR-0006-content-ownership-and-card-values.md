# ADR-0006：正式内容所有权与卡牌金额单一来源

## 状态

已接受。

## 背景

v0.3.0 要求玩法设计交付 8 张正式卡、3 个敌人和 1 个遭遇，但原所有权表只授予玩法设计 `data/cards/**`，没有明确 `data/enemies/**` 与 `data/encounters/**`。同时，架构约定要求平衡数值来自 `data/balance/**`，而卡牌定义又包含伤害、护盾、费用和状态层数。如果不明确边界，容易形成两份卡牌事实源。

## 决策

### 内容所有权

- `data/cards/**`、`data/enemies/**`、`data/encounters/**` 由玩法设计唯一维护。
- `data/schema/**` 由本地数据层唯一维护。
- 其他角色只能读取正式内容，并通过角色报告提出修改请求。

### 数值来源

- 卡牌和具体能力自身的效果、费用、目标与状态层数以对应内容定义中的稳定 ID 为唯一来源。
- `data/balance/**` 只保存全局战斗参数、成长经济、掉落和抽卡概率等跨内容参数。
- 数值设计负责审核卡牌金额和整体曲线，但不得在 balance 中复制同 ID 卡牌定义。
- 若需要批量调参，应由数值设计提出参数变更建议，再由玩法设计更新唯一内容定义并运行 schema 与规则测试。

### 评审门

- 内容 ID 必须唯一，卡牌引用不得使用显示名称或脚本路径。
- 正式敌人和遭遇必须通过 schema，并引用现存卡牌与敌人 ID。
- 数值调参不得引入 UI 特判、玩法 ID 分支或第二份卡牌表。

## 备选方案

1. 所有卡牌金额移入 balance：会让效果语义和参数分居两处，增加跨文件同步成本。
2. 数值角色直接维护卡牌副本：会形成同 ID 双事实源，已否决。
3. 数值设计只审核并建议，玩法设计更新唯一内容：保留内容完整定义，同时允许独立平衡审查，采用本方案。

## 后果

- 玩法设计可以补齐正式敌人和遭遇内容，无需再等待所有权裁决。
- 数值调整需要跨角色建议与一次内容提交，但不会产生双份卡牌数据。
- Schema 继续由本地数据层独占，内容语义由玩法设计负责。
