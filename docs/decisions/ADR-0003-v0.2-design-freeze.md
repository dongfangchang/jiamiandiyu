# ADR-0003：v0.2.0 玩法与产品决策冻结

## 状态

已接受，作为 v0.3.0 的实现前提。

## 背景

玩法、数值和 UI 报告对出牌模式、首版途径、抽卡池、晋升失败代价、节点数量和状态字段命名提出了不同草案。以下决策用于消除歧义。

## 决策

### 战斗操作

首版采用“玩家逐张出牌 + 三列即时目标”。

- 玩家选择手牌、支付灵性、选择目标并立即结算，然后可继续出牌或结束回合。
- 三列用于敌人位置和目标关系，不实现持续召唤物、六格自动牌阵或自动寻敌。
- `PlayCardCommand(card_instance_id, target_id?)` 和 `EndTurnCommand` 是战斗命令。
- UI 本地选择/取消不是领域命令；最终合法性由玩法层返回。

### 首版途径

首版只实现“占卜家”，演示范围从序列 9 晋升到序列 8。其他途径进入候选池，不进入首版数据。

### 抽卡池

首版抽卡包含：

- 人格牌
- 灵界回响
- 封印物

关键基础人格和推进所需关键卡通过初始解锁或固定掉落获得。抽卡提供构筑变化，不作为唯一进阶钥匙。

### 首次晋升

首次晋升试炼为“被篡改的讣告”三段式轻量仪式：

- 目标时长 30—90 秒。
- 玩家依据界面已有线索选择/排列，不依赖外部小说知识。
- 失败增加 2 点污染，不消耗晋升材料，可重试。
- 到达污染 10 时本次探索失败，保留局外收藏和已确认奖励。

### 探索结构

完整首版路线采用：

- 2 次白天行动选择。
- 3 场普通战斗。
- 1 个休息/恢复节点。
- 1 场精英战。
- 1 场首领战。

v0.3.0 垂直切片只做一个新游戏到单场战斗结算的最小链路，不实现完整路线。

### 存档检查点

保存点：

- 每日开始。
- 战斗结算并领取结果后。
- 抽卡、升级或晋升提交后。

v0.2.0/v0.3.0 不支持战斗中恢复。UI 必须在进入战斗前明确提示退出将回到最近检查点。

### 字段命名

- 运行状态统一使用 `corruption`。
- 中文显示文案为“污染”。
- UI 原有的 `pollution` 字段必须改为读取应用层提供的 `corruption` 语义；不得同时保留两个运行字段。
- 被注视度使用 `attention`。

### 高胜率谨慎构筑

数值草案中的聚合谨慎构筑胜率约 99.46%，不能作为最终体验接受。

- 首版加入敌方压力递增规则：从战斗第 7 回合起，每经过一个完整敌方回合，所有仍存活敌人的基础攻击增加 1；相同战斗内可叠加，战斗结束后清除。
- UI 需要显示“敌方压力”及当前增量，规则由玩法层快照提供。
- 该规则在 v0.3.0 接入真实逐张出牌后重新模拟；不得仅靠继续改生命数值掩盖拖延问题。

### 数值状态

当前生命、灵性、卡牌费用、奖励、抽卡概率与保底仅冻结为“首轮可实施草案”，v0.3.0 真实战斗后必须重新采样。单抽 2 券、两轮后晋升暂作为目标节奏，不视为最终平衡。

## 后果

- UI 已有三列战斗线框基本保持，但必须更新排序和状态字段。
- 玩法实现以逐张出牌为唯一方案。
- 数值层需要新增敌方压力参数并重新模拟。
- 本地数据层需要为 `corruption` 与检查点存档提供 schema。
- 抽卡不能成为卡关唯一解法。
