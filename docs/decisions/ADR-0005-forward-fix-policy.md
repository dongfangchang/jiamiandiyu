# ADR-0005：优先前向修复，限制代码回滚

## 状态

已接受。

## 背景

项目已经有多个角色并行提交模块。直接把整个工作区回滚到旧检查点，会丢失已验证的玩法、数据层、UI 和数值成果，也可能让其他角色基于过期接口继续开发。回滚应只用于避免更大的运行或数据风险。

## 决策

默认修复顺序：

```text
复现
  -> 定位根因
  -> 评估影响面
  -> 前向修复或替换局部模块
  -> 回归验证
```

只有以下情况允许回滚：

- 游戏无法启动、无法进入核心流程或持续崩溃。
- 存档、用户数据或项目文件面临破坏风险。
- 当前结构无法安全前向修复，继续修改会显著扩大影响面。
- 用户明确要求。

逻辑错误、UI 错误、数值错误或其他仍可运行的缺陷，优先保留现有实现，修复根因或替换局部模块。

任何回滚必须由产品经理记录：

- 故障症状和复现步骤。
- 为什么不能安全前向修复。
- 目标 Git 检查点。
- 受影响文件和对其他角色工作的影响。
- 恢复范围、保留范围和用户可见后果。
- 回归验证与重新集成计划。

禁止使用 `git reset`、`git checkout --` 等命令静默丢弃未提交工作。

## 后果

- 已验证成果得到保留，降低多角色协作丢失工作的风险。
- 普通缺陷需要更准确地定位根因，不能以回滚代替分析。
- 运行阻断型故障仍保留快速止损路径。
- 产品经理必须审阅回滚请求，不能用回滚掩盖接口设计错误。

## 检查点门

- 每条 S1/S2 Bug 记录是否说明了前向修复或局部替换方案。
- 回滚是否具备明确审批、范围和恢复计划。
- 回滚后是否运行完整回归并重新同步角色文档。
- 未因修复一个局部模块而覆盖其他角色的无关修改。
