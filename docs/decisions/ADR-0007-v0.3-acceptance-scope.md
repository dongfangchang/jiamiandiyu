# ADR-0007：v0.3.0 教学战验收范围

## 状态

已接受，v0.3.0 最终美术复验与全量回归已完成。

## 背景

v0.3.0 已形成从启动、新游戏、正式内容加载、逐张出牌、胜负结算、战后检查点到继续读取的真实链路。真实引擎采样显示，正常激进、均衡和防守策略在首场双敌人遭遇中均为 100% 胜率；压力诊断策略可以触发第 5、7、9 回合的压力，但会因不主动击杀而失败。

若把这场战斗视为完整难度曲线，100% 胜率不可接受。若把它作为教学战，则当前参数适合验证操作、事件、压力和检查点主链。

## 决策

1. v0.3.0 首场战斗明确定位为“教学战”。
2. 教学战必须让玩家理解选牌、选目标、灵性、护盾、敌方意图、压力和胜负结算，不承担长期难度曲线。
3. 100% 正常策略胜率可作为本版本已知风险保留；不得用硬编码分支或隐藏规则制造失败。
4. v0.3.0 关闭不要求实现抽卡、白天、地图、完整奖励或晋升。
5. UI 与美术仍是两个独立角色。美术提交候选资产，UI 必须完成实际界面审稿；在 UI 复验通过并重跑全量测试前，版本只能标记“验证中”。

## 关闭门槛

- 正式 PNG 全部位于 `assets/game/**`，不存在长期双份维护。
- 三敌人和战斗背景接入实际 UI；8 张卡面缩略和状态图标至少完成适配或被明确列入风险。
- UI 对美术给出“通过/退回/UI-only 适配”结论。
- 启动、真实战斗、结算、保存、返回标题、继续读取集成测试通过。
- 玩法、基础设施、UI、集成、数值和主场景 headless 检查全部退出码为 0。
- Git 工作区在版本检查点前通过 `git diff --check`，并记录检查点提交。

## 后果

- v0.3.0 可作为短时试玩版本尽快交付。
- 难度平衡在后续版本通过更多敌人、不同遭遇和卡牌调整解决。
- 后续不得把教学战胜率当作完整游戏平衡结论。
