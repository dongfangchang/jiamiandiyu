# ADR-0031：架构整治期（R0–R4）与单一事实源原则

状态：已采纳（用户授权架构师起草，2026-11-24）
日期：2026-11-24

## 背景

v0.8–v0.85 近 80 个版本以表现层迭代为主，只叠加不回收。架构审查（`docs/architecture/REVIEW_2026-11-24.md`）发现以下问题：

- UI 复刻战斗公式，并按显示字符串判断规则。
- 玩法层硬编码中文旁白和平衡数值，旁白还被写入存档。
- 卡图路径有 4 个定义源，内容数据按 4 代版本目录叠加加载。
- 约 3,000 行死代码。
- 没有统一测试入口，且有测试钉死旧版本号，必然失败。

## 决策

1. v0.85.0 关版后，进入**架构整治期**，按 `docs/architecture/ROADMAP.md` 的 R0–R4 推进，预计 v0.86–v0.91。整治期暂停新的表现层特性和内容扩展。
2. 整治期内 R1–R4 为**行为不变的重构**，以 R0 建立的黄金回放作为判定标准。
3. 采纳 `docs/architecture/TARGET_ARCHITECTURE.md` 作为目标形态，核心原则如下：
   - **规则只在 gameplay**。UI 需要的"能否/多少"由快照字段提供。新增只读快照字段不算改规则，冻结期可以做。
   - **文案不在 gameplay**。gameplay 只输出 ID，存档只存 ID。
   - **内容只有一份当前定义**：`data/manifest.json` 加扁平内容目录，不再按版本号新建内容目录。
   - **资源路径只在注册表**：`data/registry/assets.json`，UI 中禁止出现 `res://assets/game/` 字面量。
   - **测试按行为命名**，禁止断言版本号、禁止读源码文本、禁止访问私有成员。
4. 新载体或新实现验收通过的**同一版本**，删除旧实现和只为它存在的测试探针，不再"为探针保留"。
5. 新增"架构师"职责，负责 `docs/architecture/**`、跨层重构条目的拆分与评审。产品经理保留版本和范围的最终裁决权。

## 影响

- 存档预计升到 `save_version: 6`（R2-11），需要单独的迁移说明，并补全 v1–v5 的旧档 fixture。
- 内容目录扁平化后，`data/**/v0.x.0/` 旧目录按归档政策移出，不直接删除。
- `PROJECT_CHARTER §5.2` 中的"3D 场景"一条，需由产品经理修订为"仅限日记桌面书表现层，不扩展到战斗和大地图"（R0-10）。

## 回滚

每个 R 条目独立提交。若某条导致黄金回放变化或真窗口回归，前向修复；如果确实无法安全前向修复，按 AGENTS §8 记录后回滚该条提交，不影响其他条目。
