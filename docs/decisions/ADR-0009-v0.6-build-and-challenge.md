# ADR-0009：v0.6 优先离线构建与可重复挑战

## 状态

已接受。

## 背景

`v0.5.0` 已完成首次序列晋升的完整垂直切片，并通过自动路线采样、UI 审稿和全量回归。
当前仍依赖项目内便携 Godot 可执行文件启动，且玩家完成序列 8 后缺少明确的重复游玩目标。

## 决策

`v0.6.0` 同时完成两项有限目标：

1. 使用与本机 Godot 4.7.2 精确匹配的官方导出模板，生成可独立启动的 Windows 构建，并在项目目录外进行启动与完整路线验证。
2. 为序列 8 之后的玩家增加至少一条可重复挑战路线和三个数据驱动挑战修饰。修饰必须改变战斗或构筑决策，不能只提高敌人生命。

挑战继续复用既有 RouteEngine、BattleEngine、ProgressionEngine、身份、抽卡、升级和检查点，不创建第二套流程规则。

## 备选方案

- 只做导出，不增加内容：交付清晰，但序列晋升后仍缺少持续游玩目标。
- 直接扩展第二途径或多城市：内容量过大，会破坏当前低成本迭代节奏。
- 只增加新的固定章节：可增强叙事，但不能快速验证挑战/构筑重复性。

## 后果

- 本版本优先保证离线可交付和重复游玩，不承诺第二条途径。
- 若挑战需要存档结构变化，必须使用显式迁移；若不需要，保持 `save_version: 3`。
- 构建产物和测试夹具必须分离，游戏运行不得依赖 `.tools/`、网络或编辑器。
- 真实试玩暴露的问题进入补丁版本，不用虚增血量或回滚已验证功能解决。
