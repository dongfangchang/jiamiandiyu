# ADR-0010：v0.7 卡组构筑与第二挑战

## 状态

已接受，作为 `v0.7.0` 开发基线。

## 背景

`v0.6.0` 已形成独立 Windows 构建、序列 8 后挑战、挑战奖励和 v4 存档。当前抽卡已经扩大收藏、升级已经改变卡牌效果，但玩家没有直接选择出战牌组，抽卡与升级对构筑的影响仍偏间接。

## 决策

`v0.7.0` 聚焦两项有限能力：

1. 增加可保存的卡组编辑、三套牌组预设和出战牌组选择。首版固定选择 8 张唯一卡牌，只能使用已拥有、已实现且可升级池中的正式卡牌。
2. 扩充占卜家卡池至 16 张，并增加第二个可重复挑战。第二挑战必须复用既有 RouteEngine、BattleEngine、ProgressionEngine 和 Checkpoint，不派生第二套规则。

第二挑战可以复用首次路线节点，但必须通过数据驱动的遭遇变体、节点覆盖或挑战修饰形成新的决策。不得只增加敌人生命。

## 解锁与存档

- 第一挑战完成后，记录稳定的 `challenge_completed_ids`。
- 第二挑战至少要求序列 8 和第一挑战完成；UI 不自行推导解锁。
- 牌组预设、当前牌组、第二挑战解锁和最近挑战状态进入版本化存档。
- 若存档升级，必须保留 v1/v2/v3/v4 迁移和损坏档保护。

## 事实源边界

- 卡牌效果、卡牌金额、升级定义和卡牌显示信息只在 `data/cards/**`。
- 卡组规则、预设合法性、挑战解锁和路线覆盖语义由玩法领域拥有。
- 全局经济、抽卡概率和挑战全局参数在 `data/balance/**`。
- schema 和迁移由本地数据层拥有。
- UI 只显示只读快照并发送命令，不重新计算合法性、解锁或构筑收益。

## 后果

- 抽卡和升级将直接影响下一次出战牌组选择。
- 初始拥有卡牌需要至少达到 8 张，保证第一次进入构筑时存在合法牌组。
- 卡池扩展会增大升级与抽卡经济验证范围，必须先冻结卡牌 effect 闭集再进入 UI 接线。
- 第二挑战继续使用同一占卜家途径，不扩展 22 途径、多城市或开放世界。

## 拒绝的替代方案

- 只增加卡牌但不做牌组编辑：抽卡变化难转化为玩家决策。
- 直接增加第二途径：内容与经济规模会超过本次迭代边界。
- 将第二挑战做成纯数值血量副本：不能验证构筑差异性。
- 复制一套 Deck/RouteEngine：会产生两套规则和存档口径。
