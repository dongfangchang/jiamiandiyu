# ADR-0001：产品与技术基线

## 状态

已接受，作为 v0.1.0 基线。

## 背景

项目为单人离线体验，用户要求包含升级和抽卡，希望快速做出可玩版本。此前讨论过调查解谜、塔罗会桌游、假神经营和牌阵卡牌。用户明确不希望解谜成为主玩法，但允许在途径晋升中保留微量解谜。

## 决策

采用《假面低语》方向：

- 白天身份扮演与夜间牌阵战斗构成双阶段循环。
- 抽卡获取人格、封印物和灵界回响。
- 序列晋升由确定性的进度、资源和短仪式试炼共同决定。
- 首版只做一条可玩路线，优先形成 20—30 分钟闭环。
- Godot 4.7.2 + GDScript，仅离线本地运行。
- 用户所说的后端实现为本地数据与基础设施层，不建设服务器。
- 多智能体通过版本化文档和独立角色报告协作，产品经理负责裁决。

## 未选择方案

### 调查解谜为主

与用户“不要解谜”的偏好冲突，文本与线索内容成本高。

### 塔罗会经营或假神模拟为主

叙事潜力强，但需要大量事件文本和角色内容，不利于短期形成卡牌战斗闭环。

### 完整自动战斗

实现成本低，但玩家决策不足，抽卡与升级容易退化为数值比较。是否采用自动行动仍交给玩法设计在状态机阶段对比。

## 后果

优点：

- 卡牌、抽卡和升级共享一套清晰核心循环。
- 现有身份牌与封印物美术可进入首版。
- 单机架构简单，适合个人维护。

代价：

- 必须先冻结领域状态和 UI 命令接口，不能让 UI 与规则同时定义。
- 抽卡需要保底和确定性获取，避免随机性破坏短流程。
- 微量仪式必须严格限时，不扩展成独立解谜系统。

## 后续检查

在 v0.2.0 必须决定：

- 逐张出牌或自动行动的最终方案。
- 首条可玩途径。
- 抽卡池组成。
- 首个晋升试炼主题。
